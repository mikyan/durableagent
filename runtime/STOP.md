# Durable stop and control ownership

T11 adds a native stop path to the existing submission and managed execution authorities. Scoped device results, artifact identities, earlier failures and limits are recorded in [the T11 evidence](../docs/evidence/t11/README.md).

`NativeInputStore.requestStop` commits the original action identity, monotonically increasing control version, stopped generation and pending SDK abort before acknowledging the request. The UI and the notification use this same operation. A repeated action reads the durable result. A notification contains the expected control version, so an old action cannot stop a later explicit input. Draft text itself never opens a generation.

The SDK remains the only conversation/task scheduler. `abortControlScope` uses public transactions, conversation abort and task abort to cover the original conversation, related background work and inherited application control ownership. Admission stays serialized until the public abort operations settle and the native barrier is confirmed. Fork ownership is not inferred solely from the live task graph: a surviving fork can inherit the control owner after its original task is gone.

Every command request records its immutable operation ID, product control owner, generation, SDK conversation, executor namespace and request digest in native storage before dispatch. Native prepare/start reject stopped generations. Existing SDK execution intents are registered before recovery queries, including when the executor is offline. Registration during recovery is historical evidence, never a new execution permit. An upgraded catalogue remains unverified until this inventory completes.

The published native database moves from version 6 to 7 while preserving T16 content holds, quarantine and text-only frozen references. Published versions 1–4 retain their ordered migrations. The earlier T11 version 5 was an isolated, unpublished fixture and is not guessed to be a compatible production layout. A failed migration retains the old database and closes admission.

File effects and command processes are separate facts. The native catalogue accepts `kind: command | file` and `source: termux | saf`. The stop worker only sends Executor cancellation for command/Termux records. A file operation ID is never passed to process cancellation; a command's terminal receipt does not prove the associated original file outcome. Only matching digest/namespace evidence can settle that effect. Unknown evidence preserves the stopped generation and unresolved occupancy.

The native control service runs in `:control`, independently of the UI and Node owner. It performs a bounded user-requested job, not a background keepalive scheduler. An urgent Binder message is checked against the durable pending barrier before reaching the owner. When the owner ceases to make progress, reconstruction targets only this app's own Node process. It does not kill the Termux app, guess remote process IDs, or broaden cancellation by command similarity. Failed control delivery leaves the barrier unresolved.

Short native admission runs separately from slower external verification. New stops in an active namespace advance its requested work version, triggering another sweep; worker exit and request handoff share the same lock. A new explicit request arriving at the deadline may create a bounded follow-on job. An unknown effect by itself never starts an endless retry loop. Notification admission waits at most 1500 ms to acquire the native lease before the action begins and exposes a safe failure category when its result cannot be confirmed.

Native data access uses a stable OS lease before each action. UI stores keep their immediate busy result. The trusted synchronous runtime may wait up to one second to acquire that lease, before the action begins. This does not retry a transaction, an SDK submission, an external command, or an action whose commit response was lost. The control worker can retry acquisition within its original bounded job deadline. The interruption tests preserve their original 1.6-second writer hold and 9-second reconstruction deadline.

The UI distinguishes a saved stop request, pending SDK interruption, unresolved external effects and confirmed stopped scope. Permission for system notifications is requested through the explicit conversation-details action. Notification content is private on the lock screen; its control action is an immutable, explicit pending intent. Neither permission refusal nor service-start refusal is evidence that a command has stopped.

The T12 recovery lifecycle and T17 OEM matrix remain separate. A scoped Android emulator result is not Samsung/Xiaomi, pre-unlock, or all-background-policy evidence. The linked validation matrix retains the initial notification failure whose exact admission cause could not be recovered; later successful runs do not retroactively establish its cause.

T10's later file coordination will serialize arbitrary shell commands that share one environment. The T11 validation baseline can currently run two independent T09 command scopes; that evidence does not authorize bypassing the later coordinator. Combined validation must use a separate fixture-owned external scope or two provably disjoint eligible scopes to verify isolation.
