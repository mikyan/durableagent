# Termux 安装来源与兼容策略

本指南对应 [#22](https://github.com/mikyan/durableagent/issues/22) 和[兼容策略契约](specs/termux-compatibility.md)。2026-11-05 用户要求取消只接受两份 Termux 0.118.3 APK 的生产限制，保留来源核验和首次初始化后的自动启动。0.118.3 仍是 T03 历史测试的固定基线，不是后续版本的唯一准入条件。

## 安装和首次连接

应用“工具 → 本地执行 → 安装来源与兼容说明”提供两个入口，分别由外部浏览器打开 [Termux GitHub 官方发布页](https://github.com/termux/termux-app/releases)和 [F-Droid 官方页面](https://f-droid.org/packages/com.termux/)。按钮不会自动下载、安装或更新，也不把外站加载到应用的特权 WebView。

已有 Termux 应保留现有安装渠道和数据。不能为了连接而直接卸载、跨渠道覆盖或清空数据；同一包名不意味着不同渠道可以覆盖安装。新安装完成首次打开后，在本应用复制完整初始化命令，到 Termux 执行，再返回点击“连接执行环境”并完成系统授权。

初始化会复用具备所需能力的 Python 和 OpenSSL，不要求某个补丁版本。缺包时使用现有 Termux apt 源安装 `python`、`openssl-tool`；若安装计划需要更改或移除已有依赖，会停止并说明原因。已装运行时能力不足也会停止，不自动替换、升级或降级。能力检查仅使用独立临时目录，检查通过前不改已有脚本、属性、配对或执行账本。

## 来源核验与能力检查

| 来源 | 来源确认方式 | 联网条件 |
| --- | --- | --- |
| 官方 GitHub 发行 APK | 公共测试签名加完整安装包摘要；摘要必须匹配已知官方发行物或官方对应 release 的校验记录 | 内置已知安装物和已成功核验的同一安装物可离线使用。其他安装物只在用户显式点击连接时请求官方校验记录 |
| 官方 F-Droid 签名 APK | 使用[上游固定版本记录的独立 F-Droid 签名身份](https://github.com/termux/termux-app/blob/5b657c6adf4304e5198951ce815fe0205dcac29c/termux-shared/src/main/java/com/termux/shared/termux/TermuxConstants.java)核验 | 来源判断不需要联网查询 GitHub |
| 未识别签名、尚未支持的打包形式或无法确认的安装物 | 不派发执行命令，并说明当前阻塞原因 | 不会在后台反复联网或将未知来源自动加入信任范围 |

GitHub 发行包使用公开测试密钥，只有同一证书不能证明 APK 来自官方发布页；因此不会把取消版本限制实现为仅保留包名／证书检查。已成功核验的记录只对对应安装物有效，更新 APK 后重新判断来源。[上游签名说明](https://github.com/termux/termux-app#github)

来源可信后，应用仍检查系统授权和公开外部命令接口，并执行真实 bootstrap、协议及执行端身份握手。已有配对仍须匹配原客户端身份、执行端身份及账本；不自动清除配对，不借重连重发未核验的命令。安装来源被认可不表示任意该渠道版本、Android／ROM 或所有软件包已完成设备验收。

后台恢复只使用离线来源核验结果。未确认的新安装物需要用户返回界面显式连接；恢复不会隐式联网获取发行资料。首次显式连接允许包含来源核验和执行端启动的有界等待，界面最多等待 60 秒响应；超时不表示安装物已经不兼容，也不授权重新执行原工作。

## 常见阻塞

| 界面情况 | 处理方式 |
| --- | --- |
| 安装包来源尚未确认 | 联网后点击“连接执行环境”；若仍无法确认，检查下载来源，保留现有安装与数据 |
| 暂时无法获取官方发行记录 | 网络或发行服务暂不可用时稍后重试；无需重新初始化或卸载 Termux |
| 安装来源或打包形式暂不支持 | 保留现有 Termux，核对上述支持范围；不把它当成需要降级／清空的指令 |
| 外部命令接口不兼容 | 核对安装渠道和版本；来源可信并不保证所需接口存在 |
| 初始化提示 `RUNTIME_CAPABILITY_UNSUPPORTED` | 保留现有环境，根据随附的失败阶段核对 Python、SQLite、进程监督或 TLS 能力；不要通过清空数据、重置配对或盲目降级处理 |
| 初始化提示安装需要更改已有依赖 | 当前缺包无法只靠添加依赖完成安装；保留原环境，先评估依赖更新影响，不自动执行更新 |
| 缺少安装、系统授权或首次初始化 | 按页面流程完成对应前置条件；不要把网络核验失败误当作初始化失败 |
| Termux 被系统强行停止 | 明确打开 Termux 一次后返回，无需重新初始化；普通进程退出与强行停止分开处理 |
