# 由 Android 应用直接托管 Pi Durable

移动端的启动和中断恢复需要由应用自身管理，因此选择由本应用的运行宿主托管 `pi-durable` Agent 内核，并在本应用内复用 `pi-ai`，而不是以完整桌面 Node/HTTP 后端或 `pi-coding-agent` 为产品基础。
相比直接移植 Pi Pocket 等现成产品，这条路线减少了对桌面服务形态的依赖，但需要提供 Android 生命周期、存储、执行与模型传输适配，并接受上游持久化和扩展契约带来的迁移成本。
这里的应用托管不是把主 Agent 放进外部 Termux 后由界面遥控；Termux 只作为命令执行环境，具体命令行集成方式、UI 框架及打包方式由后续决策分别确定。
