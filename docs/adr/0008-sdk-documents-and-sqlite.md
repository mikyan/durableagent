# 普通业务数据复用 SDK 持久化，以 SQLite 为主存储设计目标

2026-11-03，用户通过 Q19、Q20 确认：普通应用业务元数据优先使用 SDK 自定义 document／必要 entry，共享 SDK Storage 以 SQLite 后端为设计目标，而不是另建竞争的消息与主业务数据权威，以减少双写并复用受支持的事务。
代价是依赖 SDK 的作用域、时间语义、迁移和启动契约，并承担 SQLite 驱动与耐久性验收；原生控制、凭据、草稿、尚未接纳的投递记录及外部执行事实仍按各自职责组织，不承诺跨来源原子提交。
该决定没有选定 Node 或原生桥接驱动，也不是 Android 兼容已验证或开始工程的授权；具体字段、文档政策和保留规则见[数据设计](../data-design.md)。
