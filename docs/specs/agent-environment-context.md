# Agent 运行环境上下文

2026-11-05 用户要求 Agent 明确知道自己运行在 Android、本地工具由 Termux 提供以及当前工作区。以下为该要求的代理细化，不改变配对、执行身份或恢复契约。

每次实际 SDK 模型请求准备时，由固定核心的 `application_environment` 系统提示段提供最小环境事实：

- 应用核心运行在 Android 应用进程；Bash 与路径型读写由同机独立 Termux UID 执行。SAF 原文件工具通过 Android Provider 授权，content URI 不能当作 Termux 路径。
- Android API、系统版本、设备支持 ABI 及应用进程位数只采用原生 `Build`／`Process` 提供的白名单值，不推测 Termux 命令 ABI，也不暴露设备标识、应用私有目录、凭据或密钥。
- 工作区采用该次 SDK `ManagedEnvironment` 的已采用绑定与位置版本。提供实际用于命令 cwd 的绑定路径；已有真实位置检查成功时可附最近核验的规范路径。不能回退到应用 SDK／数据库目录或应用进程 cwd。
- 绑定缺失、已关闭、位置未核验、身份改变及已有执行端核验记录分别表达。工具声明不等于工具当前可用；历史核验不冒充当前在线，实际工具入口继续校验来源、权限、配对、位置和能力。

提示渲染只读取已提供的原生白名单与固定核心内存观测，不调用网络、`connect`、`ping`、目录检查或任何工具，不更改配对、位置和执行账本。观测只由原本已有的实际检查更新；无法确认的事实明确标为未确认。路径等字段作为 JSON 数据转义，不能成为系统指令。

本变更不增加自动重放或自动替换环境行为。构建与类型检查只能确认接线，模型是否理解这些事实及各状态的实际呈现仍须按用户确认的验证范围记录。
