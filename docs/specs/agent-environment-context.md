# Agent 运行环境上下文

2026-11-05 用户要求 Agent 明确知道自己运行在 Android、本地工具由 Termux 提供以及当前工作区。以下为该要求的代理细化，不改变配对、执行身份或恢复契约。

每次实际 SDK 模型请求准备时，由固定核心的 `application_environment` 系统提示段提供最小环境事实：

- 应用核心运行在 Android 应用进程；Bash 与路径型读写由同机独立 Termux UID 执行。SAF 原文件工具通过 Android Provider 授权，content URI 不能当作 Termux 路径。
- Android API、系统版本、设备支持 ABI 及应用进程位数只采用原生 `Build`／`Process` 提供的白名单值，不推测 Termux 命令 ABI，也不暴露设备标识、应用私有目录、凭据或密钥。
- 工作区采用该次 SDK `ManagedEnvironment` 的已采用绑定与位置版本。提供实际用于命令 cwd 的绑定路径；已有真实位置检查成功时可附最近核验的规范路径。不能回退到应用 SDK／数据库目录或应用进程 cwd。
- 绑定缺失、已关闭、位置未核验、身份改变及已有执行端核验记录分别表达。工具声明不等于工具当前可用；历史核验不冒充当前在线，实际工具入口继续校验来源、权限、配对、位置和能力。

提示渲染只读取已提供的原生白名单与固定核心内存观测，不调用网络、`connect`、`ping`、目录检查或任何工具，不更改配对、位置和执行账本。观测只由原本已有的实际检查更新；无法确认的事实明确标为未确认。路径等字段作为 JSON 数据转义，不能成为系统指令。

本变更不增加自动重放或自动替换环境行为。构建与类型检查只能确认接线，模型是否理解这些事实及各状态的实际呈现仍须按用户确认的验证范围记录。

用户第 0 项的真实模型验收由独立 instrumentation 方法 `ExecutionRealProviderTest#realMimoIdentifiesAndroidAndItsActualTermuxWorkspace` 执行，需显式 `realProvider=true` 和既有一次性加密凭据 capsule。测试经过真实 React 输入／发送、SDK、MiMo 请求与受管 Termux 执行；提示不填入期望的平台、提供者、工作区、UID 或设备数值，模型必须从系统环境说明和实际工具输出作答。

该验收沿用 `execution-real` 的显式 Bash 工具选择约束，要求一次只读 `uname`／`getprop`／`pwd`／`id` 与唯一标记输出，再由模型给出结构化答案。断言范围包含唯一完成回执、执行身份与摘要、原始 stdout、原生 Android API／设备 ABI／独立 Termux UID、当前已采用工作区路径，以及经独立受信 `inspectWorkspace` 读取的实际规范目录。记录明确标注工具选择受约束，不作为自由工具规划的证明。

验证传输在实际发送边界仅提取白名单证据：第一次请求的系统段环境字段、是否说明独立 Termux UID／提供 Bash，以及第二次请求中模型工具调用的名称、参数键和命令 SHA-256。不保留请求正文或原始工具参数。验收要求首发系统段已包含真实环境，且模型命令与只读命令完全一致、未自行 `cd` 或指定 cwd，避免由输出反推环境或手动纠正目录而掩盖接线问题。

应用在整个请求与执行窗口必须保持前台；若暂停或停止则验收失败，不能靠将 Termux 切到前台通过。只构建测试包不代表真机通过；设备结果与失败证据由运行者另行记录。测试不修改正式 Provider 路由、不主动连接或重配执行端、不打印模型凭据。
