# Termux 来源与能力兼容

2026-11-05，用户要求修改只接受两份 Termux 0.118.3 APK 的生产限制，并连接 Galaxy S23 继续实测。执行跟踪：[GitHub #22](https://github.com/mikyan/durableagent/issues/22)。本记录补充首版契约，不改写 T03 的历史固定版本证据。

## 行为

来源可信与执行能力分别判断。版本号用于识别发行物及诊断，不单独决定能否连接。首次初始化后继续按需自动启动，保留配对、执行账本、停止代次和未知效果核验。

- GitHub 官方构建的公开测试签名不能单独证明来源。历史已核实 APK 离线认可；其他安装物须与固定官方仓库发布的完整 APK 摘要一致。
- 新 GitHub 安装物的来源核验只由用户明确点击连接触发。使用固定 HTTPS 官方来源，限制跳转、响应大小和总时长；成功结果只缓存对应的实际安装物。应用不上传 APK、会话、文件或模型凭据。
- 后台普通执行与自动恢复只读取本地认可结果，不隐式联网获取发行物元数据。安装物变化后重新核验；断网、限流或来源服务失败不伪装为已证实不可信，也不自动更换或重置已有环境。
- F-Droid 官方私有签名作为独立渠道的信任依据，与 GitHub 公开测试签名区别处理。来源通过不代表任意版本已实测；仍检查权限、启动结果、执行端协议、能力以及已配对身份。其他渠道不静默按这两类认可。
- 缺安装、待来源核验、核验暂不可用、不支持的来源、权限/初始化缺失和能力不兼容分别提供可操作说明。官方来源链接在外部浏览器打开，不给外站随包 WebView 的原生能力。

以上来源策略、缓存边界和错误分类为本次代理细化。禁止为了兼容替换、卸载、清空或迁移现有 Termux；不放宽执行端认证，不将未知执行当作未开始重发。

## 验证

通过来源检查公开接口与 HTTPS 边界覆盖可信/不匹配摘要、未识别渠道、缓存失效、离线恢复、超时和错误分类；在 UI 的真实请求/响应入口覆盖提示及等待期限。设备层使用实际官方安装物：原支持安装继续工作，至少一种旧硬编码会拒绝的官方 APK 通过来源和真实执行检查。

根任务独占设备。S23 使用既有 Debug 签名原位升级，保留产品数据和现有 Termux；先复查启动异常，再完成实际初始化/连接、普通启动、真实模型与原文件恢复的可执行范围。额外 APK 在独立空白模拟器验证，不替换 S23 的 Termux。

记录实际版本、APK 摘要、来源、设备/页大小、执行步骤及结果。既有 MiMo01、S23 初次锁占用和其他 T17 未测项，仅在取得对应证据后分别更新；发布成功及工单关闭不是功能验收替代品。
