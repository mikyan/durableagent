# T11：用户停止后旧工作不再复活

## What to build

用户在会话或原生通知中请求停止，即使 Agent JavaScript 无响应也能得到有依据的状态。停止意图跨进程退出保留，旧发送、模型响应、工具回调与恢复计时器不能重新启动已停止的工作；外部命令未确认结束时如实显示。

## Acceptance criteria

- [ ] JS 卡死后停止、立即明确新发送、重建宿主并到达旧 abort 时，新意图可先原生保存但不能先于旧停止的 SDK abort 完成范围核验而接纳；旧 abort 不撤回或终止新的输入。新的控制代次本身不能绕过这道屏障。
- [ ] 会话和原生停止入口调用同一原生控制能力，不依赖 JS 回复；UI 断开或销毁不取消已经接收的停止动作。
- [ ] 原生停止意图与控制代次先耐久保存，再确认“停止请求已保存”；保存失败明确报告，不把内存标记、停止按钮变化或杀进程冒充已耐久。
- [ ] 停止后禁止旧代次的待确认发送重投、工具启动、模型新请求和后台后继工作；SDK safe replay、迟到回调和重新连接不能绕过此限制。
- [ ] JS 正常时通过 SDK 公开 abort 能力处理相应会话及已接纳的相关后台任务／后代，撤回适用的排队输入；不直接修改 SDK 私有表，也不把 Harness.close 当主动停止。
- [ ] SDK abort 可能启用调度，其入口仍通过全局就绪检查与停止 fence；JS 不响应时原生仍能停止受管执行并在必要时终止／重建本应用运行宿主，重建不重新启动旧工作。
- [ ] T09 的取消按执行身份传到 Termux，核验实际进程和可监督后代；确认全部相关受管执行结束才显示停止完成，无法核验时显示“停止已请求，外部结果待核验”。
- [ ] 停止请求重复点击／重复投递保持幂等，不扩大到其他会话或非受管 Termux 工作；迟到退出收据可补充事实，但不能解除停止意图或发起后继动作。
- [ ] 停止后立即杀宿主、重启应用、恢复网络、触发旧 wake／重试、收到旧模型流和命令回调，旧工作始终不复活；停止记录不可用时恢复入口保持关闭并明确原因。
- [ ] 停止前尚未接纳的发送保持已停止／不可自动投递状态，不能借重新生成 request ID 绕过；新编辑的草稿保留，绝不自动发送。
- [ ] 用户明确发起新输入可以开启新的工作代次，旧身份仍不能投递；有未决外部效果时，新工作仍遵守结果核验和位置占用约束，不以新代次假装旧效果已结束。

## Blocked by

- T07：可靠发送意图与接纳核验。
- T09：受管命令执行及停止核验。

## Implementation notes

- 自主细化：会话级 SDK abort 不按应用控制代次过滤。在同一会话中串行完成旧停止的 SDK abort 提交与范围核验，再允许新代次意图进入 SDK；此前原生保留新意图并显示等待停止完成。外部未知效果仍独立保持占用，不因这道接纳屏障解除而视为取消成功。
- 已确认：Kotlin 拥有不依赖 JS 的紧急控制与原生停止事实；TypeScript 协调应用行为；SDK 自己保存执行／取消状态；Termux 只报告实际执行证据。
- 自主细化：原生为会话维护单调控制代次和停止 fence，旧工作携带其产生时的代次；停止关闭该代次的执行资格。只有明确的新用户发送建立新资格，重连、自动恢复和同次发送重试不能解除 fence。
- 自主细化：停止先落原生控制记录，再取消网络和外部执行，待 SDK 可用且启动条件合格后提交其公开 abort。不存在跨原生、SDK、Termux 的一次事务，必须逐项核验并保留未决状态。
- 原生终止 JS 只用于恢复控制能力，不能制造会话成功终态。SDK background abort 的覆盖范围有限，应用 fence 仍须阻止后来到达的旧代次后台创建／执行。
- 本票不改变首次解锁前不可访问 CE 的约束；控制记录尚不可读时不启动模型／命令，也不借 DE 缓存秘密绕过。

## Test seam

以应用公开停止／观察 Interface 驱动“有模型请求和真实受管子进程的会话”，注入 JS 不响应、SDK abort 延迟、原生持久化失败、进程重开及乱序旧消息。断言可见停止语义与实际执行效果，原生入口需独立于 JS 的设备测试。复用 T07 提交身份和 T09 执行证据，避免另造一套测试专用状态机。

## Scope and execution boundary

不承诺能终止所有任意脱离监督的进程，不建立操作审批队列，不把用户停止扩展为整个 Termux 的 kill-all。实现、停止进程及设备故障实验需后续明确执行授权，只使用专用受管测试工作；ready-for-agent 不是本次已有紧急控制／设备操作权限。
