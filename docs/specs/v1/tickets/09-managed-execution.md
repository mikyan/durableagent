# T09：从会话执行命令并在失联后核验同一次执行

## What to build

用户在会话中让 Agent 执行一个真实 Termux 命令，可以看到增量输出、退出结果和异常原因。应用或连接中断后，同一次命令能够查询已有执行、续取输出并核验结果；不能因没收到回调就重复启动有副作用的命令。

## Acceptance criteria

- [ ] 会话通过统一工具环境调用已验证的 Termux 执行端；工具环境向 SDK 提供 ExecutionEnv，UI 不直接发 Intent、读 Termux 私有路径或控制进程。
- [ ] 首次下发前持久保存稳定执行身份、所属会话／工具调用、固定请求内容、工作位置版本和控制代次；同一次重试保持这些关联，主动执行相同文本可以有新的身份。
- [ ] 执行端按执行身份接纳去重；相同身份不同内容或上下文明确拒绝。重复下发、ACK 丢失和重连均不能启动第二个命令；无法确认曾否启动时返回未知而非自动新建。
- [ ] 对外区分确认未启动、已接纳／运行、确认完成、停止待核验、确认停止、结果不明；SDK 存储收据、命令接纳和真实副作用完成不混为一种成功。
- [ ] 字符串命令经 shell、argv 参数不再经 shell 重解析；cwd、环境继承、超时和最终执行参数按契约生效，最后执行路径保留统一策略检查位置。
- [ ] stdout／stderr 增量解码并保留流来源和顺序信息；输出窗口、丢弃计数、完整原始输出引用及背压有界且可检验。大输出不通过无界 IPC 帧或最终回调内存缓存运输。
- [ ] 重连按执行身份与输出位置续取；重复片段可识别，缺口明确报告，旧连接或旧命令的输出／终态不能串入新执行；完整输出由同一工具环境读取。
- [ ] 按执行身份取消与超时只影响本次受管命令及可确认的后代；取消完成回调不是终止证明，PID 重用不误杀其他 Termux 工作。脱离监督的后代无法确认时保留不确定结果。
- [ ] 在意图持久化、执行端接纳、进程启动、效果发生、退出记录和 SDK 结果提交各窗口中断，恢复均先查询证据；已完成不重跑，结果不明不允许模型无条件再发等效命令绕过保护。
- [ ] 执行连接限定本机且进行认证、版本和实例核验；不对外监听，不向任意 WebView 内容开放原生执行，不在日志／命令输出泄露通道凭据。
- [ ] 通过最小会话页面演示成功命令、失败命令、大输出、连接断开后核验和取消；断线本身不释放仍在运行或未决执行的占用。

## Implementation notes

- 已确认：工具环境统一拥有文件／命令边界和执行事实，TypeScript 核心根据事实协调 SDK；Termux 不负责会话调度。SDK Shell.exec 没有天然执行键，不能假设只换环境 Adapter 已覆盖持久关联。
- 自主细化：在 SDK 支持的工具／任务包装处取得稳定调用关联并立即保存执行身份；应用必要关联保存在生命周期足够长的应用记录中，不能只留在终态会退休的 task memo。Termux 保存去重、启动、退出和输出证据。命令内容摘要仅用于一致性检查，不充当唯一执行键。
- 自主细化：正常结果和重连结果均通过同一执行 Interface 返回。可重放包装只允许重连已有执行，或在证据确认未启动且当前条件允许时启动一次；原始任意 Bash 不因包装而获得无条件 safe replay。
- 初次执行与恢复都校验控制代次及最终参数。停止 fence 由 T11 完成，工作区互斥由 T10 完成，省流策略由 T13 完成；本票提供统一入口而非三套旁路。
- 本票按 T03 通过的传输固化有界协议。副作用与数据库提交无法形成跨 UID 原子事务，不能以写完状态文件宣称外部效果恰好一次。

## Test seam

主要从应用会话提交／观察入口用确定性模型脚本驱动真实工具；在 ExecutionEnv 边界复用固定 SDK 的环境 conformance cases，并注入接纳／启动／退出／提交窗口故障。真实 Termux 子进程、流式输出和停止核验必须实际验证，不读取内部状态字段来替代文件效果和进程证据。

## Scope and execution boundary

不新增交互终端页面、远程执行服务、主 Agent 后端或任意副作用 exactly-once 承诺。工程实现、命令执行、安装依赖及目标设备操作均需后续明确执行授权；本次只整理 spec。ready-for-agent 不允许据此操作用户文件或现有 Termux 工作。
