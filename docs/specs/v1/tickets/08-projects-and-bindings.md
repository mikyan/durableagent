# T08：让会话使用稳定项目位置并拒绝忙时改绑

状态：设计工单；分诊标签：`ready-for-agent`。实施状态与阻塞关系以 GitHub 为准。

## What to build

用户可以建立和选择项目；未关联项目的会话直接使用默认工作区。输入被接纳时，应用保存实际使用的位置绑定，并在排队、执行及恢复期间保持该绑定。相关输入、后代工作或受管效果尚未核清时，修改会话项目关联或正在使用的共享位置会明确被拒绝；条件解除后，用户可以重新发起修改。

## Acceptance criteria

- [ ] 新建未关联项目的会话无需创建目录，使用共同默认工作区；选择具名项目后正确解析其工作区，界面能辨认当前项目及实际位置状态。
- [ ] 项目／工作区记录具有稳定身份，名称修改不被当作位置改变；多个会话引用同一项目或工作区时，查询显示一致共享事实，不各自复制成独立权威。
- [ ] 接纳输入时核验并保存位置绑定；之后排队输入、追加输入、自动后继 run 及恢复执行均使用已采用版本，不因读取当前全局配置而途中换目录。
- [ ] 有未结算已接纳输入、仍可执行任务或后代、其他会话对共享位置的活动使用、未决受管执行或仍可能投递的意图预期时，对相关关联／位置修改返回明确不可更改原因；不能只凭 UI idle 或 waitForIdle 结果放开修改。
- [ ] 被拒绝的修改没有悄悄写入为待生效配置；相关使用解除后不会自动应用旧请求。用户重新发起修改才产生新配置，且之后新输入采用新绑定。
- [ ] 将关联修改与意图持久化、SDK 接纳、停止及外部结果确认并发执行，结果只允许完整一致的旧绑定或新绑定；配置不一致明确失败，不让旧发送悄悄执行于新目录。
- [ ] 同一发送在 ACK 丢失后重试，仍指向原接纳绑定；已结算且仅供历史追溯的绑定不永久占用位置。仍有未知效果时保持阻塞，不用伪造结束解除修改限制。
- [ ] 受支持的内部 task conversation 显式继承必要执行绑定；之后接收输入仍保留该规则，同时不会因拥有绑定或内部 fork 自动出现在产品会话列表。
- [ ] 原件移动、目录不可用、系统授权撤销或执行环境变化时，显示对应不可用事实；稳定绑定不被当成永久授权或文件快照，也不自动回退默认目录执行。
- [ ] 受控位置 Adapter 将两个不同工作区记录解析为同一实际目录时，两者呈现同一位置身份或明确的未能消歧状态；本票向协调策略暴露真实冲突依据，不能因记录 ID 不同宣称互不冲突。
- [ ] UI 及 Agent／扩展的项目查询与修改都使用同一应用 Interface 和上述前置条件；需要另一位置时可以另开会话选择另一可用项目，不自动增加会话私有目录或会话级任意路径覆盖。

## Blocked by

- T07：可靠发送和 SDK 接纳事务，提供稳定意图、位置预期、admission map 与初次位置绑定。

## Implementation notes

- 产品会话、项目、工作区和实际位置身份各自独立；共享应用事实继续通过 SDK 应用 document 保存。名称等普通元数据遵循当前值政策，执行及恢复所需绑定版本保留。
- 所有主动接纳入口共用位置核验与绑定政策；SDK 没有通用 admission 校验 hook，不能只保护 UI 入口。内部 conversation 创建显式供应绑定，产品可见性另行登记。
- 配置修改与投递通过共同的应用协调入口落实前置条件；原生待投递意图和 SDK 状态不在同一事务内，必须持有可核验预期并处理并发与中断，不能把先后两次查询当成原子判断。
- 使用期判断覆盖 pending 输入、可能执行的相关任务及后台后代、共享位置其他使用者、待确认意图与未知外部效果。generation taskId 会变化，idle 不证明引用全部结束；历史记录留存本身也不能永久阻止修改。
- 位置解析与实际访问能力来自工具环境 Adapter。T08 用受控 Adapter 验证绑定、别名事实和错误传播；T10 负责同实际目录别名、重叠位置及未知写范围的真实写入协调。本票不提前宣称已解决真实文件系统全部别名。
- 工作区不是安全沙箱；命令显式使用其他合法位置的权限和写入协调仍由实际执行策略处理，不因当前绑定而承诺全文件系统隔离。

## Test seam

从应用 Interface 创建／选择项目、发送输入、修改关联并观察结果，使用真实 SDK 事务和受控位置／任务／外部效果 Adapter。覆盖队列与自动后继 run、子 conversation、共享引用、确认丢失及位置变更并发；断言实际传给执行环境的绑定和用户可见拒绝原因。别名与运行事实使用确定性样例，真实目录协调在 T10 验证。没有既有自动化测试可直接沿用；SDK 输入／继承研究和 Module 设计提供契约依据。

## Scope and execution boundary

本票交付项目选择—输入绑定—忙时修改拒绝—释放后重新修改的可演示闭环。不新增项目级模型继承、分支聊天、跨位置自动输入队列、沙箱或完整文件管理器。T10 的真实冲突协调不是本票在受控 Adapter 上验证位置政策的前置条件，但未通过 T10 不能宣称实际并发写安全。

当前只编写 spec／工单；后续实现、安装、SDK 运行、设备操作和真实文件修改须获得对应执行授权。`ready-for-agent` 不是执行授权或兼容性证明。
