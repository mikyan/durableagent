# T10：真实原文件操作与同工作区写入协调

## What to build

用户在默认工作区或项目会话中处理已授权的真实手机文件，文件工具与 Bash 看见同一对象；多个会话共享文件时，潜在写入保守串行。结果能由另一个读取入口或系统文件应用复查，而不只是应用内副本变化。

## Acceptance criteria

- [ ] 已知受管修改提供可查询的会话／执行关联、实际位置及原件／副本标记；取得前后内容时给出有界文本 diff，供会话文件变更区域显示。任意 shell 范围未知、二进制差异或缺少前值时明确标记不可得，不用示例 diff 代替真实结果。
- [ ] 未关联项目的多个会话使用同一默认工作区；项目会话使用 T08 固定的绑定。工作区身份、实际目录、执行环境和当前访问能力分别核验，恢复不重新解析成当前全局目录。
- [ ] 在同一环境内完成“文件工具读取→Bash 修改→文件工具复查”，canonical path、文本／二进制内容和完整输出引用指向相同对象，不把 Termux 路径交给本应用本地文件 API 猜测访问。
- [ ] 对实际已授权原文件完成读取、修改并由独立入口验证；若使用中转，只有原对象回写成功才报告修改完成，原件变化／回写失败明确保留结果不明或冲突。
- [ ] SAF URI 通过其真实访问能力处理，不转换成虚构 shell 路径；Provider 不支持的操作、授权撤销、原件移动／删除和存储暂不可用分别报告，不拿缓存成功冒充原件成功。
- [ ] 文件 Interface 的必要二进制读取、追加／截断、刷新、重命名、目录遍历和错误语义通过契约检查；打开后被重命名的文件 reader 仍读取原对象，监听重连缺口报告 overflow。
- [ ] 代表性依赖安装／构建在合适的工具工作区验证执行位和链接语义；共享存储的 noexec／链接限制明确呈现，不默认把所有项目放在共享存储后宣布完整兼容。
- [ ] 同一实际目录的不同工作区记录／可识别别名归入同一协调域；Bash、文件修改和扩展的潜在写入统一排队。无法识别写入范围的 shell／其他命令取得执行环境级独占占用，与该环境内所有有范围的写占用及其他环境级占用双向冲突。
- [ ] 有冲突范围的两个会话写入不会重叠；分别验证“局部写入先运行、未知范围命令等待”和“未知范围命令先运行、任意局部写入等待”，不能只验证两个全局占用互斥。纯聊天、状态查询和确定无副作用的读取仍可继续，排队原因可见，停止等待中的工作不执行其写入。
- [ ] 协调占用在宿主重开后依据持久关联和 T09 执行证据恢复；断线、SDK idle、lease 超时或进程退出不能自动释放仍有未决效果的占用。
- [ ] 已接纳输入、相关后台／后代工作和未决执行仍在使用绑定时，配置修改按 T08 拒绝；仅剩历史引用不会永久占用。实际文件及其他应用的修改不被宣称冻结或全局锁住。
- [ ] 在原文件已修改而应用未保存结果时终止宿主，重新核验效果后报告，不盲目覆盖；工作区访问不是安全沙箱，显式访问其他合法位置仍受真实授权及执行约束。

## Blocked by

- T08：项目、默认工作区与接纳时位置绑定。
- T09：受管命令执行及结果核验。

## Implementation notes

- 自主细化：资源协调身份跨原生与 Termux Adapter，覆盖同一原件及父子目录关系；不能因跨 UID／不同入口而取得两把互不冲突的锁。别名关系无法排除时使用覆盖相关可写入口的共同保守串行域。补测未知 shell 跨目录写、父子目录写和原生回写与 Bash 同时修改同一原件。
- 已确认：核心协调工作区，工具环境落实文件与命令；Q31 在接纳事务固定位置，使用中拒绝变更，不建立悄悄待生效的位置队列。
- 自主细化：以执行环境身份和核验后的实际目录身份建立保守协调域，未知别名关系不能作为并发安全证明；共享位置引用关联到相同占用记录。派发前确定已知写范围或使用环境级独占；两者由同一协调器原子判断冲突，环境级独占必须排斥该环境全部局部写占用，不能只使用彼此无关的局部锁与全局锁。跨工作区的显式多位置写入按稳定顺序取得必要占用，避免互等。
- 自主细化：Termux 工作区文件由有权的执行端提供统一文件 Interface；Android 文档资源由有权的原生 Adapter 提供能力，明确原对象与表示。支持的原位访问／回写组合通过设备事实固化，不承诺所有 URI 都具备 POSIX 语义。
- 占用记录只表达应用受控执行的协调事实，不复制 SDK 调度器，也不锁住其他应用。未决执行导致长期等待时显示原因，不能伪造完成以释放占用。
- SDK 内置单文件 mutation queue 不覆盖 Bash／跨进程，不能当作本票的工作区协调实现。

## Test seam

从应用会话 Interface 驱动两个真实共享工作区会话，观察排队、文件效果和状态；SDK ExecutionEnv 边界补充文件 conformance。真实文件、SAF Provider、跨 UID 命名空间和原位回写需在受控目标设备文件上验证。输入绑定测试复用 T08 的公开接纳入口，不通过内部 generation taskId 推断工作组。

## Scope and execution boundary

不新增完整文件树、独立产物浏览器、沙箱或对外部应用写入的全局锁；不要求任意文档 Provider 对所有 CLI 透明可用。后续实施、设备授权和真实文件修改需明确执行授权，故障实验只用专用测试文件。ready-for-agent 不是本次已有文件操作许可。
