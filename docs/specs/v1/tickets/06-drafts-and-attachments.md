# T06：保存草稿并准备稳定的附件输入

实施状态与阻塞关系以 GitHub 为准；以下勾选对应本票记录的实际验证范围。

## What to build

用户在会话中编辑文字、选择图片或文件后，可以看到保存与附件准备状态；关闭界面、重开应用或 Agent JS 无响应时，已确认保存的内容仍可恢复。附件在编辑期间逐步完成本地准备，实际投递前固定采用的内容表示，来源失效、预算不足与保存失败均有明确反馈。恢复草稿不会启动会话或发送内容。

## Acceptance criteria

- [x] 在两个会话分别编辑文字，等待各自保存确认后重建界面及重开应用，恢复各自已保存版本；没有任何自动发送或模型请求。
- [x] Agent JS 尚未启动或无响应时，文字、附件草稿记录及必要内容持有关系仍能经原生保存入口确认；恢复结果不依赖原 JS 实例存活。
- [x] 默认在最后一次编辑后 250 ms 发起保存，持续编辑的最长等待为 1 s；切换会话和显式发送先 flush 当前版本。保存期间显示待保存，实际提交失败显示失败，不把内存输入当作耐久成功；测试不宣称每次按键或硬故障零丢失。
- [x] 人为打乱保存完成、清空和会话切换回调顺序，旧 revision 的保存／清空不能覆盖较新的文字或附件选择；冲突有明确结果，不以最后到达的回调决定内容。
- [x] 选择已支持的图片／文件后，界面分别显示来源引用、准备进度及实际采用表示的范围。默认准备只执行本地读取／转换，不发送未提交内容至云端，也不自动启动会话工作。
- [x] 重开后重新核验来源及必要材料；原件删除、移动或授权撤销时明确显示不可用，保留仍可恢复的文字与材料，不以缩略图、空正文或另一文件替代原定输入。
- [x] 一份已固定的附件输入版本在原件随后变化后仍保持相同内容关联和摘要；明确主动重新选择／准备产生新版本，重试不会悄悄重读并替换已固定内容。
- [x] 准备未完成时可以保存明确的未完成状态；发送流程不能将它显示为 SDK 已接纳完整内容。无法确认来源仍符合预期时停止准备并提供重新选择／发送的明确原因。
- [x] 超过当前 Provider 或设备的输入／准备预算时，明确拒绝或列出可选缩减及其影响，不静默截断正文；仅提供资源引用时明确模型尚未收到正文，不把同一数值限额套到所有原文件。
- [x] 已生成且仍是草稿或固定输入唯一恢复来源的内容，在缓存清理后仍可恢复；丢弃材料只回收经证明无引用的应用自有内容，不删除用户原件。
- [x] 使用存储失败、空间不足和原生进程中断故障注入验证：已确认版本可按已验证耐久边界恢复；未确认版本保持待确认／失败，且发送入口不越过未完成的 flush 或内容准备。
- [x] 原生存储及材料布局从首次启用起即落实私有工作数据的云备份／设备迁移排除基线；自动化配置检查覆盖本票新增存储域，真实 OEM 行为留给获授权的设备验收。

实现与全部 12 项条件的对应证据见 [T06 验收](../../../evidence/t06/README.md)。最终候选模拟器 26 项实际通过、手动 picker 另测通过；S23 所选 25/25。两台均运行原生 20 项、六个真实独立进程终止窗口、同源 SDK 策略，以及真实 MiMo PNG/完整 UTF-8 固定输入；UI PID 终止后两份草稿完整恢复。S23 锁屏可见性、最后选中页偏好、来源 provider 的合作式取消及 T07 接纳交接边界按证据解释，不扩大为全部首版/OEM 验收。

## Implementation notes

- 原生 SQLite 独立于 SDK Storage，承载文字／附件草稿、revision 及必要内容持有关系；不让 UI 或 Kotlin 直接写 SDK 内部表。原生进程统一使用 Kotlin 持久化实现，以短事务串行修改；转换及大内容 I/O 不占用事务等待。
- 使用 revision 条件写入／清空，避免旧请求覆盖新编辑。保存回执建立在实际事务提交之上，不建立在入队或标记事务成功之上；不提供跨原生存储、内容文件与 SDK 的虚假原子保证。
- 250 ms 防抖与 1 s 最长等待是代理给出的首版工程默认值，并非用户逐条指定；根据可观察延迟、实际平台及故障结果调整时保留切换／发送 flush 和失败可见的承诺。
- 固定输入表示、原件引用和原件访问能力分别保存；内容文件可外置于原生记录，使用稳定关联和完整性核验。生产存储参数、数字容量预算及支持格式应随实证记录确定，不能把未验证值宣称为设备能力。
- SDK 图片边界仍要求内联 base64；本票提供可准备和核验的表示，不以路径或 URI 替换 SDK 的图片契约。已发送内容由 T07 的发送意图引用固定版本。
- 每个受支持的原生访问入口共用同一 revision、材料持有与错误语义；多进程不依赖 SharedPreferences 的旧跨进程标志。

## Test seam

通过应用 Interface 保存、读取、观察与丢弃草稿，以真实原生持久化和受控来源／转换／Provider 能力 Adapter 验证恢复、CAS、容量与故障行为。用确定性时钟核验保存时限，用真实进程重开补足持久性证据。核心断言为可恢复内容、状态与无自动发送；不测试内部转发调用顺序。当前项目没有既有测试套件；设计先例来自深应用 Module 与原生持久化研究，不把源码研究写作已通过测试。

## Scope and execution boundary

本票完成一个可演示的编辑—保存—重开—准备输入闭环。SDK 接纳与重试由 T07 交付，完整格式转换库、全部原件归档、分享菜单导入和附件云端预处理不在本票范围。T16 后续加强全链保留、迁移及回收测试，不是推迟本票基本备份排除和引用保护的理由。

本票原设计阶段只编写 spec／工单；随后按用户的 implement-spec 及设备实验授权完成实施。后续设备操作及破坏性变更仍须对应授权。`ready-for-agent` 仅表示分诊目标，不是执行授权或已验收证明。
