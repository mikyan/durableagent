# T12：在条件恢复后继续未完成会话

## What to build

用户不需要重新发送“继续”：会话在断网、进程回收或设备重启后，等待数据、模型、执行环境和系统运行条件就绪，核验既有进度与外部效果后继续未完成工作。等待原因、重试时间和不可恢复的失败始终可见；运行时有必要的原生状态通知，工作完成后在系统允许时通知用户，主动停止保持最高优先级。

## Acceptance criteria

- [ ] 重开时依次读取原生控制、取得唯一 SDK 所有权、提供有效同步 bootstrap settings／Models、open 且不调度、装载／迁移权威配置、发布运行投影并核验执行条件；open 阶段实际调用 getter 不依赖未初始化的 Harness。所有调度入口同经就绪闸门，不只拦 resume。
- [ ] UI 退出、重建或重连仅恢复观察，不重发输入或从头创建会话；已经确认的输入和历史仍可追溯，未确认发送按 T07 核验原身份，未发送草稿绝不自动提交。
- [ ] 网络恢复、运行宿主被系统回收后获准重新启动、用户重新打开应用等场景，未完成且可继续的工作自动恢复；等待状态明确说明当前阻塞条件。
- [ ] 设备重启后等待真实首次解锁和系统运行资格，之后尝试恢复；首次解锁后再次锁屏按已接受凭据政策允许后台模型请求，不承诺固定唤醒时间或 Direct Boot 执行。
- [ ] force-stop 不尝试绕过，等待用户重新打开；合法启动被系统或厂商策略阻止时明确显示。前台运行具有适当用途及退出路径，原生持续通知显示最小会话／运行／等待／停止状态并提供返回会话与 T11 停止入口；通知授权或渠道受限时如实说明可见性，不把 Service 或作业调度器当常驻保证。
- [ ] 恢复前核验 T09 的受管执行证据：已完成复用结果，仍运行重连观察，确认未启动才允许当前资格下启动，未知副作用暂停相关工作；不把 unsafe 的 interrupted 交给模型后允许其盲目重发绕过。
- [ ] T10 的固定位置、授权现状与占用状态恢复正确；未决效果不因 idle、连接超时、租期到期或重启被释放，缺绑定／撤销授权不会静默换目录继续。
- [ ] 模型失败、crash 和 deferred poll 尊重 SDK 的不同恢复规则；普通重试可在重新 prepare 时采用会话新选择，原 deferred handle 不改成新请求，旧连接无法恢复时明确阻塞而不换目的地重发。
- [ ] 自动重试有界、可见，展示原因、下一次尝试时间和已用额度；初始应用退避建议为 1／2／4／8／16 秒、最多 5 次，实际不得超出 SDK 更严预算，同一工作总额度不因宿主重启重置。
- [ ] SDK sleeping deadline 使用一致的 epoch 时钟；重复 wake、时钟前后调整及进程死亡后重建唤醒不会重复执行或复活已停止工作。使用 onWake 时由宿主安排合法唤醒并通过就绪闸门恢复。
- [ ] 正常 close、crash、SDK restart_limit、凭据不可用、存储失效、用户停止分别呈现；达到预算或不可核验失败时停止自动重试，不创建新的提交身份逃避终态。
- [ ] 最小闭环在真实授权测试文件上完成“处理一部分→断网或终止宿主→条件恢复→继续处理”，已完成操作不重复，最终文件结果和会话记录一致；耐久完成确认后发送可返回对应会话的 Android 完成通知，重复恢复不会反复创建同一完成通知。分别验证允许通知、拒绝授权及关闭渠道，受限时结果仍在会话可见；另验证停止后始终不复活。

- T11：耐久停止 fence。

## Implementation notes

- 已确认：Pi Durable 负责执行检查点和恢复状态机；本应用负责 Android 生命周期、运行条件、输入交接和实际执行证据协调，不复制 SDK phases 成另一套业务调度器。
- 自主细化：恢复协调只作“读取权威→核验条件／外部证据→允许 SDK 调度”的闸门。只读查询和观察可以在必要范围内工作；submit、compact、abort、等待及 wake 等可能调度的路径不能旁路。
- 自主细化：宿主重试预算与 SDK attempt／restart 计数绑定同一工作身份；退避由单个协调者安排，不在 Provider、SDK 和宿主叠加乘法重试。终态失败不自动转成新的用户请求。
- 自主细化：Kotlin 根据应用权威状态投影管理前台运行通知，完成通知依据已耐久的完成身份使用稳定通知标识更新／去重；通知仅包含必要标识和状态，不放入正文、工具输出或凭据。通知点击只打开对应会话，不触发再次发送。请求通知系统授权遵循 Android 流程；授权拒绝不取消会话结果，也不错误认定前台 Service 必然无法启动，仍履行系统要求的通知义务并准确说明抽屉可见性。
- 网络变化或平台唤醒是重新核验的触发器，不是立即执行命令。Android 的启动资格、CE 可用、凭据状态、授权与工具就绪是分别检查的事实。
- 恢复中的重复模型计费无法绝对排除，呈现已有用量与重试依据，不承诺远端 exactly-once。省流策略由 T13 接入同一闸门，不在本票另写联网分类器。

## Test seam

使用应用会话 Interface、真实 SDK／持久存储和受控模型传输跑恢复契约，再在目标 Android 进程和 Termux 执行端注入故障。复用 sleep-wake-reopen、model-crash-budget、restart-limit-and-close、exec-crash-windows 等固定版本研究用例。设备启动／锁屏与通知授权／渠道／点击返回／原生停止必须有实际系统验证，不能由 mock 成功替代；T17 负责最终整机矩阵。

## Scope and execution boundary

不承诺无限保活、固定重启唤醒时刻、零重复模型计费、跨设备恢复或任意副作用自动重做。后续工程、运行上游代码、模型调用、授权文件操作及设备故障实验均须明确执行授权；ready-for-agent 只表明工单可承接，本次没有执行这些操作。
