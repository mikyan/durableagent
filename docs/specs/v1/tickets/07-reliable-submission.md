# T07：让一次发送在中断后可靠接纳且不误重发

状态：设计工单；分诊标签：`ready-for-agent`。实施状态与阻塞关系以 GitHub 为准。

## What to build

用户明确发送后，应用耐久保存这一次发送的目标、内容与位置预期，并让用户区分待投递、接纳未确认、已接纳及后续执行状态。原生保存、SDK 接纳与回执之间发生中断时，应用核验并继续同一次发送；不读取后来编辑的新草稿，不把回执丢失变成重复发送，也不复活停止前的待投递意图。

## Acceptance criteria

- [x] 明确发送且当前草稿 flush 完成后创建稳定发送意图；无发送动作的草稿在重开、重连或恢复时不产生意图。原生意图保存失败时明确告知，SDK 未接收到该输入。
- [x] 同一意图在重启、重连、重试中保持稳定身份、目标会话、实际输入版本、内容摘要及位置预期；任一关联不一致时明确报错，不把不同内容交给同一 request ID。
- [x] 用户主动将相同正文再发一次时产生新的意图并可被独立接纳；系统不按正文相同吞掉用户明确的新发送。
- [x] 分别在原生意图提交前后、SDK 接纳提交前后、原生确认前后注入中断，恢复后同一意图至多对应一个 SDK submission；已接纳但回执丢失的输入通过核验找回原接纳结果，不追加重复历史或新执行。
- [x] 新建会话后首次发送发生中断时，可以找回已创建的产品会话，再恢复同次发送；不会因重试创建第二个产品会话，也不声称创建与首次接纳属于同一 SDK commit。
- [x] SDK 接纳失败时，接纳映射与位置绑定不留下只提交一半的组合；成功时两者与接纳结果共同可核验。原生确认仍是独立提交，其失败不能推导 SDK 未接纳。
- [x] 旧发送接纳确认到达时，用户后续编辑的草稿 revision 及附件选择保持不变；界面显示确认对应的那次发送，不以当前输入框内容补写旧意图。
- [x] 输入准备未完成、已取消、停止前未完成投递或实际运行条件不具备时，不因应用恢复自动发起该意图；原生停止事实在 JS 重建后仍生效，需明确新的用户动作才可重新发起被停止的工作。
- [x] 接纳时发现会话关联或工作位置与意图预期不符，明确显示位置不一致并拒绝悄悄改投；对已经接纳的同次重试返回原绑定，不创建新的位置绑定。
- [x] busy／排队、接纳、放入 transcript、输入结算及整个会话继续执行分别展示可观察状态；接纳不被写成模型已经读取，输入结算不被写成后台后代及外部效果全部结束。
- [x] UI、跨会话路由及扩展使用的主动输入接纳入口遵循同一身份、内容和位置核验规则；重新取得 SDK 状态可纠正丢失的通知，不以流式通知充当完整持久日志。
- [x] 所有可能启动 SDK 调度的接纳／恢复调用在配置、停止和存储就绪门槛之后执行；未就绪状态明确可见，不靠只拦 resume 或环境构造抛错阻止运行。

本地验收记录：[T07 实现与实测证据](../../../evidence/t07/README.md)。12 项在记录的平台范围内通过；当前完整 SDK/UI/真实 MiMo 组合验证来自 Android 16 / 16 KiB 模拟器，S23 仅保留较早原生候选的 11/11 实测范围。GitHub 为状态权威，T03/T17 设备门槛不因此解除。

## Implementation notes

- 新发送可建立新控制代次并先保存在原生侧，但旧停止仍有待执行的 SDK 会话 abort 时，必须等待其提交与范围核验后接纳，避免迟到旧 abort 清除新输入；本票以受控停止 Adapter 验证，T11 贯通真实原生紧急控制。
- 发送意图属于原生持久化权威，SDK 接纳后 submission／inbox／entries 承接相应权威；不复制 Agent 任务队列或 SDK 调度状态机。原生意图与 ACK 不与 SDK 自动组成跨库事务。
- 用稳定意图 ID、目标、输入版本与摘要核验同次发送。SDK requestId 仅在同一 conversation 内按同类型去重，并不比较内容；应用应在返回已有 submission 前核对自身的接纳映射和内容一致性。
- 在受支持的 SDK 事务中执行接纳，并共同保存应用 admission map 与实际位置绑定。submit(tx) 必须在第一次 table write 之前；conversation 创建已是 table write，因此创建与首次提交分开，使用稳定关联找回中间状态。事务内读写通过 tx 完成，不重入外层修改线。
- 原生 ACK 记录 SDK 接纳关联；ACK 丢失时先查询核验再重试，同一意图不能读取最新草稿或换身份。草稿清空使用对应 revision 的条件修改，不能清空后来编辑。
- 对停止前意图保留可核验的停止／取消约束，统一检查恢复入口；最终原生紧急控制与受管外部效果由相关后续票补全，本票先以受控控制 Adapter 验证不重发语义。
- 初次接纳只建立已核验的位置绑定，T08 完成项目编辑、共享位置使用期及释放政策；本票不借 generation taskId 构造独立 run 调度器。
- 保存成功、SDK 接纳、模型生成完成和外部执行效果分别提供结果；不承诺外部效果恰好一次或模型零重复计费。

## Test seam

从应用 Interface 执行发送、查询状态、重连与停止控制，使用真实 SDK 1.5.0 和持久 Storage、真实原生意图存储，加受控模型／平台／控制 Adapter。围绕两套存储的提交与确认边界注入中断，断言稳定目标／内容、唯一 submission、可恢复 ACK 及新草稿保留。SDK 接纳契约和原生事务语义已有研究依据，本仓库尚无既有测试套件；不以 mock 返回成功替代真实提交边界验证。

## Scope and execution boundary

本票交付一次发送从用户动作到可核验 SDK 接纳的完整闭环。完整项目编辑由 T08 交付，外部命令副作用、系统唤醒和紧急停止全链由对应生命周期票交付。这里不新增任务中心、操作审批、跨设备同步或自行覆盖 SDK 私有表的修复入口。

当前只编写 spec／工单；后续实现、安装、运行 SDK／APK、设备实验及破坏性测试须获得对应执行授权。`ready-for-agent` 不代表允许执行或已经通过真机验收。
