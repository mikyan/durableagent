# T14：随包扩展提供真实界面能力与明确的跨会话转交

## What to build

开发者通过一份薄的应用扩展描述关联可选的界面与 Agent 入口，能够交付自定义 React 交互，也能单独提供工具／提示词能力。用户可在普通会话中查询其他会话状态、创建会话或向指定会话转交请求；转交遵守同一发送与位置约束，默认输入仍由当前会话处理。

## Acceptance criteria

- [x] 一个随包功能可为 UI-only、Agent-only 或两侧都有；每种均有真实可演示用例。UI-only 使用已有查询／订阅，无需空 Agent 扩展或虚假工具。
- [x] UI 宿主仅加载 UI 代码并共用宿主 React；运行宿主仅加载 Agent 贡献。薄描述只关联稳定身份与入口，不试图跨进程共享 React 函数或 SDK 闭包。
- [x] UI-only 用例呈现当前会话历史的自定义时间线／交互并支持分页和状态订阅；关闭页面释放其 UI 订阅，不停止会话。该用例证明表达能力，不要求直接移植现有 timeline 插件。
- [x] 至少一个内置业务能力使用同一扩展路径，工具、提示词、执行协作与扩展状态复用 SDK 接入点；不出现第二个 Agent registry 或任务调度器。
- [x] 意外重复应用身份或最终 SDK 扩展身份在装配时报错；不同扩展对工具／section 的有意覆盖仍按 SDK 的选择顺序生效，重复 task 名称按 SDK 契约失败。
- [x] “已打包”“SDK 已安装”“会话已选择”“页面已挂载”分别呈现或解释；缺失贡献不会被静默标成可用，页面状态不充当后台执行开关。
- [x] 普通会话能够按明确目标查询另一个产品会话的状态；查询不复制其完整上下文，也不为每条输入自动路由。
- [x] 创建／转交返回可追踪的目标会话与提交结果；跨会话转交通过 T07 的统一接纳路径，使用稳定提交身份，重试不会产生第二次输入，且不能绕过 T08 的位置预期检查。
- [x] 目标会话不存在、状态不允许、位置预期失效或来源会话的操作已被停止时，转交明确失败／等待；同名标题不能代替稳定目标身份。
- [x] Agent 设置能力与 UI 设置入口使用同一模型配置／宿主 Interface，普通查询不暴露 Key；扩展不能从公共能力移除停止闸门、绕过系统授权或直接争写 SDK 数据库。
- [x] 扩展初始化失败、挂载异常、订阅断开可诊断且不冒充会话完成；运行中已有调用使用的资源由实际所有者释放，不能以 SDK uninstall 或 UI 卸载等同于自动取消和 dispose。

本地验收记录：[T14 实现与实测证据](../../../evidence/t14/README.md)。11 项按记录范围通过：实际 Android 16 / 16 KiB 模拟器的 UI 时间线、真实 SDK/双 SQLite、原生与 SDK 共 6 个进程死亡窗口、真实 MiMo 正常／丢 ACK 转交及后续定点回归。运行时 147 项、UI 67 项通过。各候选的失败、修复和重测分别保留，未合并成不存在的单轮全绿结果；没有本票 S23/Xiaomi 实测或真实 Termux 文件执行结论。GitHub 仍为实施状态权威。

## Implementation notes

**已确认约束：**一份薄描述关联两侧入口，UI-only 不要求后台贡献；Agent 贡献交给 SDK registry。持久化与恢复、平台检查、停止和实际执行控制留在固定核心。首版按 YOLO，不建设空审批框架。

**本轮自主细化：**随包描述由构建时可校验的稳定功能身份、可选 UI 入口、可选 Agent 入口组成；宿主注入当前会话身份及有限的查询／动作客户端。需要额外资源时由创建它的 Module 负责生命周期，不为纯贡献建立通用插件启停状态机。公开动作均核验调用上下文与目标，转交保留来源关联但不默认混入来源会话全部历史。

跨会话路由作为一个内置 Agent 扩展演示完整路径：查询可见产品会话 → 选定稳定目标 → 提交一份明确请求 → 返回接纳或失败状态。创建新的产品会话遵守 T04 的创建幂等语义；内部 task conversation 的上下文继承不改变产品登记规则。实际接纳不只校验 UI 入口，Agent 与扩展也调用同一策略。

**仍需验证：**两侧 bundle 的依赖隔离、SDK 覆盖语义及 Android 重连行为。应用装配诊断是本轮设计，不将其描述为 SDK 自带的依赖求解或 setup／dispose 协议。

## Test seam

通过应用 Interface 驱动扩展与转交，使用真实 SDK registry 与受控模型响应，观察目标会话的实际输入和状态。对 UI-only 使用组件交互与分页／订阅契约测试，外加双侧打包检查。验证有意覆盖、误重复、重复转交与停止竞态，不读取私有 registry 内部结构。现有原型与 SDK 示例只提供设计先例，项目尚无已运行生产测试。

## Scope and execution boundary

不交付手机动态安装、插件市场、热重载、通用依赖解析、第二个聊天入口、独立任务中心或专门多 Agent 编排。可信随包扩展不是恶意代码沙箱。本轮只编写／发布工单，不执行产品实现或设备操作。
