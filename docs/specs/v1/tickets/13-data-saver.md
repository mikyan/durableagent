# T13：省流模式约束受控工具且保留本地工作

## What to build

用户开启省流模式后，在受限网络上仍能使用模型通信和受控纯本地能力；非模型联网或联网行为不明的工具等待条件恢复，或由用户明确临时放行。运行中网络改变时同样生效，并在会话中显示具体等待／停止原因。

## Acceptance criteria

- [ ] 省流设置通过应用统一配置／查询入口可见；Android 提供当前网络事实，界面和持久“曾是 Wi-Fi”标志不能替代实时检查。未知网络条件按保守受限处理并说明原因。
- [ ] 受限网络下，已配置模型连接的模型通信及可证明受控的纯本地操作继续；受控非模型联网等待，不把所有 Bash 一律暂停。
- [ ] 未纳管或联网行为不明的命令按未知处理，不因可执行文件路径、随包来源或程序名称就认定任意参数、脚本和子进程纯本地。
- [ ] 分类与执行检查覆盖最终 command／argv、cwd、环境、工具 prepare 修改、嵌套调用及 SDK safe replay；只在 beforeTool 或 UI 提交入口检查不能通过验收。
- [ ] 用户可对一个明确的等待操作临时放行；界面说明目标、范围和有效条件，放行不会关闭全局省流，不自动变成同一程序所有未来调用的白名单。
- [ ] 临时放行与稳定执行身份关联，断线重连同一次执行不扩大范围；新执行、内容改变、用户停止或放行失效必须重新判断，不能用旧回调恢复资格。
- [ ] 执行中从非受限网络切换为受限网络，未获放行的受管非模型联网／未知操作被停止并核验结果；模型通信和受控纯本地操作继续，检测与处置延迟有可复现记录。
- [ ] 网络策略停止与用户主动停止原因分开；恢复非受限网络只重新判断资格，已发生或结果不明的副作用不自动重跑，只有确认未启动或本身可安全继续的工作自动恢复。
- [ ] 系统网络事件重复、抖动、乱序和宿主重开不造成重复执行、无限重试或解除 T11 的停止 fence；策略状态丢失时先核验而非默认放行。
- [ ] 会话清楚显示“省流等待”“临时放行中”“网络变化后结果待核验”等原因；不称为操作审批，不引入通用批准队列。
- [ ] 验证矩阵包含模型流、受控本地文件操作、联网下载、行为不明脚本、子进程、safe replay 和运行中切网；结果说明这是一套受控工具策略，不承诺任意代码硬断网或切网瞬间零流量。

## Blocked by

- T09：统一受管执行路径及结果核验。
- T11：原生停止控制与执行 fence。

## Implementation notes

- 已确认：省流是独立应用策略，YOLO 不取消它；受控工具统一遵守，模型通信例外不是任意远端通信的万能通行证。
- 自主细化：网络限制依据 Android 的计费／受限事实及应用设置；无法得到可信事实时保持保守等待。模型请求通过模型 Module 识别，不让一般工具伪装为模型通信。
- 自主细化：纯本地资格来自受控能力契约和实际参数范围，任意 shell 默认未知。可信随包扩展须经宿主能力使用网络，普通扩展声明不能免除最终执行检查；这不构成恶意代码沙箱。
- 自主细化：临时放行默认仅覆盖所选执行身份及本次受限网络期间，结束、停止或离开该期间后失效；允许连接重建读取同一许可，不能借内容变更获得新授权。
- 自主细化：切网处置选择停止受影响受管操作并核验，不承诺无损冻结任意进程。TypeScript 解释策略，Kotlin 提供网络事实和不依赖 JS 的控制，Termux 执行端响应受管取消；外部未知结果阻止盲重放。

## Test seam

从应用公开设置／会话观察／单次放行入口测试，复用 T09 执行与 T11 原生取消路径。模型和联网工具使用受控网络端点测量实际请求；在 Android 上切换网络并验证真实子进程。断言对外行为和有限流量事实，不把检查了某个 hook 当策略生效。

## Scope and execution boundary

不建设 VPN、防火墙、恶意代码隔离、逐文件云端审批或通用操作审批系统；不承诺已发出的流量可撤回。工程实现、网络实验、模型请求和设备切网操作均需后续明确执行授权，本次仅写 spec；ready-for-agent 不等于这些操作已获许可。
