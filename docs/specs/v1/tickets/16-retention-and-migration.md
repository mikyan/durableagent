# T16：在容量、迁移及恢复故障下保住必要工作数据

状态：设计工单；分诊标签：`ready-for-agent`。实施状态与阻塞关系以 GitHub 为准。

## What to build

用户长期使用会话时，正式历史及仍需引用的输入内容不会按时间消失。空间不足、版本不兼容、迁移中断和凭据不可用时，应用明确说明影响并保留原数据；只回收可重建或证明无引用的应用材料。私有工作数据的系统备份排除得到全链核验，界面不把本地保留、上下文压缩或隐藏说成备份或彻底删除。

## Acceptance criteria

- [ ] 在扫描出无引用候选之后、实际删除之前新增草稿／发送／SDK 引用，新增引用获得有效持有或明确重试，内容不会被并发清理；原生到 SDK 交接中断时，原所有者仍持有唯一恢复材料。
- [ ] 推进保留时钟并执行维护后，正式会话历史、有效输入引用的内容、仍需恢复的发送意图及必要控制事实保持可读／可核验；压缩模型上下文不删除原历史。
- [ ] 缓存及应用临时材料清理只回收可重建或已证明无引用的内容；草稿唯一恢复材料、待接纳发送、fork／历史引用及未知执行结果所需证据均不被误删，用户原文件和工作区内容不被顺带清理。
- [ ] 在原生存储、SDK 存储及必要内容写入处分别注入空间不足／保存失败，界面报告对应失败，不显示虚假成功；已存在数据仍保留，不通过静默删除历史腾空间。
- [ ] 正常升级读取旧版应用记录后，支持的迁移保持会话关联、输入版本、稳定发送身份、停止事实和引用一致；只读访问和实际提交后的持久化差异符合 SDK 契约。
- [ ] 迁移中断、迁移函数失败、存储结构不兼容及遇到更新版本时，保留原数据并给出可行动的状态，不静默清空重建；可能影响执行正确性时阻止调度，能安全读取的既有内容可只读展示。
- [ ] 在恢复过程中存在旧意图、停止记录、凭据不可用或未知外部效果时，不因迁移成功或记录重新出现就重放旧工作；接纳和外部效果分别核验，无法核验的副作用继续阻塞相关操作。
- [ ] 密钥缺失／永久失效、暂不可用、密文损坏和格式不兼容分别产生明确状态；不降级明文、不把新建同名保护密钥称为恢复成功、不删除其他会话与草稿。
- [ ] 完整盘点会话／执行数据、业务元数据、草稿、发送意图、输入材料、原生控制和凭据所在存储域；配置检查证明云备份、设备迁移及目标版本适用的其他通道均有明确排除，不能仅检查 allowBackup=false。
- [ ] 在另行授权的独立测试安装中，用假秘密及可识别工作记录核验目标 ROM 的云／设备迁移行为，记录系统构建、通道与局限；未验证或不遵从规则时报告失败，不宣称所有厂商和未来通道绝不会带出数据。
- [ ] 用户可见说明区分当前安装内保留、升级保留和卸载／清数据／丢机／换机后的缺失；不承诺系统自动恢复。即使发现来自不受支持迁移的记录，也不能未经一致性核验恢复为可执行工作。
- [ ] 首版不提供声称彻底删除单会话历史的交互；隐藏、撤回、reset、压缩或 retireDoc 不被标成物理删除或安全擦除，也不新增归档／隐藏功能冒充完成该能力。
- [ ] 故障验收产出包含各来源的提交边界、保留对象、迁移前后可观察结果与秘密标记扫描；进程被杀、系统重启和硬故障耐久性分别记录，不用其中一种测试替代全部保证。

## Implementation notes

- 自主细化：由原生内容持有 Module 统一登记新持有和候选隔离；发布引用前先耐久登记，跨来源交接核验完成前不释放旧持有。扫描只产生候选，删除前对内容版本条件隔离并再次核验；隔离与新增持有互斥，新引用使清理失效或得到可重试结果。来源不可读即延期清理，不能把扫描瞬间的无引用当永久事实。
- 本票加强跨来源保留、引用回收、迁移及故障验证；基本备份排除、提交失败可见和必要内容保护必须从各存储首次启用的票开始实施，不能留到本票才启用。
- 按所有者和引用维护材料生命周期：SDK 权威继续由单一活动 Session 通过公开 Interface 修改，原生草稿／意图和工具环境执行证据保留自己的权威。不存在跨库、Keystore、原件与 Termux 的自动共同事务。
- 普通元数据只承诺当前值，但仍用于投递、旧请求、历史解释与外部核验的版本不可当缓存。完整性不确定时保留材料并报告问题，不能据 idle 或当前页面不可见推定无引用。
- SDK document 的值迁移不能改变已有 scope、history 或 fork 政策；类型化读取迁移不等于写盘，SDK 打开不等于全库迁移完成。迁移错误不触发破坏性默认重置；安全只读与允许调度分开判断。
- 备份排除覆盖实际布局和各目标通道；本地迁移保护副本如确有必要，同样属于受保留与排除政策约束的私有工作数据，不是新增云备份或可移植恢复功能。
- Keystore 保护密钥与凭据密文分开；凭据异常不靠重建同名密钥修复，秘密不得流入常规请求选项、日志和广播。保留旧连接定义不等于保留失效秘密或允许旧服务继续执行。
- SDK 固定版本没有公开删除 conversation／entry／submission 的 Interface；不绕过内部表做级联清除，不将文档 retirement 或 SQLite revision 行回收扩大为安全擦除保证。
- 可测试的故障分类和恢复结果应通过既有应用 Interface 暴露，避免新增独立任务中心或数据管理平台。具体 SQLite 同步与日志参数必须结合目标运行时验收，不默认承诺所有硬故障零丢失。

## Test seam

以应用 Interface 驱动保存、发送、恢复、配置和维护，使用真实 SDK／原生持久化及受控工具环境事实注入，观察数据与执行资格在故障前后的变化。跨来源恢复重点验证不误发、不丢唯一证据及错误可见；迁移使用固定旧版本样本。备份与密钥边界另需获授权的 Android 独立测试安装，使用合成秘密，不使用真实用户凭据或工作文件。当前没有现成测试套件；原生存储、SDK 迁移及退休研究是契约先例，不是项目验收结果。

## Scope and execution boundary

本票交付已有保存／发送／执行链的容量和迁移故障闭环，不承诺无限容量、完整原件备份、永久完整 stdout、系统自动换机恢复、云同步、凭据导出、单会话物理删除或安全擦除。规则只覆盖本应用支持的存储与系统备份接入，不能统一控制外部 Termux、用户原件、root 提取或任意厂商工具。

当前只编写 spec／工单。后续实现、运行、迁移演练、设备安装、清数据／卸载、备份恢复及其他破坏性故障实验均须另获对应执行授权，并使用独立测试数据。`ready-for-agent` 不是执行授权，制定本票也不代表任何故障或设备验收已经完成。
