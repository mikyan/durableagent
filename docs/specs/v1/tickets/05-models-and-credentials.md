# T05：配置模型凭据并按会话独立选择模型

## What to build

用户在模型页面配置 API Key 和所需连接，选择新会话默认模型，并在某个会话中单独切换模型；应用通过 Pi AI 发起真实模型通信，清楚显示凭据、连接或网络失败。共享配置不改变其他会话的模型选择，恢复旧请求也不悄悄改投新的服务。

## Acceptance criteria

- [x] 模型页面可配置受支持的 API Key 连接、查看实际可解析模型及凭据是否已配置；提交后完成一轮真实模型聊天。具体通过的 Provider／端点与运行环境记录为支持矩阵，不把整个 SDK 目录标成已验收。
- [x] 配置页明确说明聊天、附件及工具结果可能发送给所选云端模型；不增加逐文件上传审批或通用审批队列。
- [x] 新会话显式保存创建时的默认模型选择；修改默认值只影响以后创建的产品会话。一个会话改模型不改变另一个会话，不复制 API Key 到会话或项目。
- [x] 后续新 generation prepare 可以采用新模型；已发出的请求不因设置改变被中断或重新发送。普通重试重新 prepare、正常 close 后原请求恢复、deferred poll、已选 compaction 的行为分别符合固定 SDK 契约。
- [x] 改变目的地或不兼容协议定义时创建新连接身份；旧选择／checkpoint 仍解析到保留的旧定义。新连接不自动继承旧凭据，也不自动切换既有会话。
- [x] 端点核验包含公开连接配置和鉴权返回的端点覆盖；未知账号兼容性、已停用连接或无法恢复的旧响应明确失败／等待，不静默改投、换模型或新建替代请求。
- [x] Keystore 持有保护密钥，API Key 密文保存在应用私有 CE 存储；没有明文落盘降级。首次解锁前等待，首次解锁后再次锁屏不附加每次认证或当前解锁要求，但仍遵守系统运行限制。
- [x] 凭据暂不可用、密钥丢失／永久失效、密文损坏和版本不兼容分别可见；需要时要求重配 API Key，不删除会话历史或草稿，不把新建同名密钥宣称为恢复旧密文。
- [x] 使用合成秘密测试普通查询、广播、错误、日志、会话 documents、generation／compaction checkpoints，证明它们不保存原始 Key 或鉴权 headers；凭据不会经 Termux 命令行或通用工具参数传递。
- [x] 配置修改成功返回前，持久配置及供 SDK 同步读取的运行投影达到一致版本；加载／迁移失败时阻止依赖该配置的调度，不用未初始化值发请求。
- [x] 凭据轮转、撤销、连接停用与在途请求并发均有可观察结果；不得承诺轮转撤回已发请求或绝不重复计费。旧定义仍被引用时不得只因 UI 不再显示而回收。

## 验收记录

实现与全部 11 项条件的证据见 [T05 验收](../../../evidence/t05/README.md)。Android 两台最终各 3/3（含共享 13 项策略与真实 MiMo），原生 vault 各 11/11；首次解锁前为实际模拟器重启，S23 为首次解锁后再次锁屏。永久失效注入、MiMo 能力范围及 T17 可见交互限制按证据解释，不扩大为所有 ROM/Provider 验收。

## Implementation notes

**已确认约束：**模型配置与凭据由应用拥有的统一 Module 提供，Provider、模型目录、传输及鉴权复用 Pi AI；会话模型选择是会话事实。Q28 的连接身份、Q32 的凭据密文保护及 Q33 的锁屏可用性已接受。

**本轮自主细化：**公开查询只给出连接定义、可用状态与凭据存在性；写凭据使用独立的窄动作，模型请求通过 CredentialStore／AuthContext 在请求时解析秘密。非秘密请求选项按允许字段构造，拒绝鉴权字段进入会被 SDK 持久化的 stream options。配置变更采用版本化发布，先完成耐久提交，再切换同步运行投影；提交后发布失败进入配置不可用状态并重新装载，不假称配置已经可执行。

连接定义与凭据轮转分开：改目的地建立新身份；同一目的地的凭据替换不证明账号相同。对依赖账号的 deferred handle，未能证明兼容时报告恢复受阻，要求明确处置旧响应；不自动以新账号重开请求。停用连接阻止新的执行解析，保留必要定义及引用，不保留失效秘密作为恢复手段。

**仍需验证：**凭据加密实现、实际密钥安全等级、目标 ROM 锁屏行为及具体 Provider 兼容性由实现与验收证据确定；不承诺所有设备具备 StrongBox，也不将同 UID 进程或可信随包扩展视为秘密隔离边界。

## Test seam

主要从应用配置／创建会话／切换模型／提交／观察 Interface 测试，使用真实 SDK 与可控 Provider 端点；按正常 close、crash、重试、deferred、compaction 分别注入改变。真实 Android 补测 Keystore、CE 首次解锁与锁屏行为。测试只断言可观察连接、请求目的地、持久状态和秘密不出现的位置，不复制 SDK 状态机。当前无生产测试先例；依据为固定 SDK 数据政策和 Android 私有数据研究。

## Scope and execution boundary

首版支持 API Key；OAuth 订阅登录、项目模型继承、凭据导出和自动跨设备恢复不在本票范围。请求过程仍需在授权进程内使用秘密，不承诺运行时被攻陷也不泄露。本次仅形成工单；真实凭据使用、运行工程与设备实验需后续执行授权。
