# T04：创建会话、接收文字回复并在重连后查看持久历史

## What to build

用户打开应用即可创建不关联项目的会话，发送文字并观察回复；重建页面或重新打开运行宿主后，仍能查看同一会话及已提交的历史。此切片使用受控模型传输贯通真实 SDK、持久存储、独立运行宿主和最小聊天页面，建立后续功能共用的应用行为 Interface。

## Acceptance criteria

2026-11-04 已按后续 `implement-spec` 指令完成本票切片。[验收证据与平台限制](../../../evidence/t04/README.md)记录模拟器完整 4/4、S23 停止／真实模型子集 2/2，以及两台设备的真实 UI 进程重建；S23 解锁后的 ActivityScenario／可见界面矩阵仍由 T17 补齐，不计作本票已经通过的实体机 UI 结果。

- [x] 新建会话不要求创建项目、选择目录或新建目录；使用稳定的默认工作区记录。一次创建重试能够找回同一产品会话。
- [x] 产品登记、SDK conversation 关联、初始模型选择在同一次 SDK 创建提交内完成；失败时不会出现可见的半个会话。创建与首次输入接纳仍是两个操作。
- [x] 两个产品会话具有独立历史与状态，共用一个 SDK Storage；任意时刻仅有一个活动 SDK Session 写入者。内部 task conversation 不自动进入产品列表。
- [x] 最小页面通过同一应用 Interface 创建／列出／打开会话、分页读取历史、提交文字、观察状态和请求停止；不获取 Harness、数据库句柄或任意原生调用能力。
- [x] 通过受控模型收到流式回复并完成提交；状态区分正在处理、等待、失败、完成，以及已显示进度与已持久记录，不以一帧流式内容作为保存证明。
- [x] 运行宿主正常关闭后重开，已提交的用户输入、回复、标题和模型选择仍可读取；无法打开存储或版本不兼容时保留原数据并显示原因。
- [x] 页面刷新、旋转或 UI 进程重建只重新获取快照和订阅，不再次提交最后输入、不创建第二个写入者，也不因页面关闭主动停止 Agent。
- [x] 订阅断开后可从当前完整状态恢复；迟到的旧连接更新不能覆盖新连接状态。取消 UI 订阅不会取消会话执行。
- [x] 配置未装载、运行宿主未就绪或协议版本不兼容时，动作明确返回可识别失败／等待原因；不通过 SDK 的 submit、wait 或 wake 旁路启动未就绪工作。
- [x] 内置最小会话能力通过薄的随包扩展登记接入，UI 与 Agent 入口分别构建；持久化、启动闸门和停止入口仍属固定核心。
- [x] 自动化验收展示一条完整路径：新建两会话 → 各自发送 → 重建 UI → 正常关闭／重开运行宿主 → 原历史可读且没有额外输入。不能用 MemoryStorage 替代持久证据。

## Implementation notes

**已确认约束：**TypeScript 核心组织应用业务，Kotlin 管理 Android 机制，React 页面只发出动作和呈现结果；SDK conversation、entries、submissions、tasks 与控制 documents 保持 SDK 权威。普通应用元数据复用 SDK documents，标题等提供当前值，不增加完整编辑审计。

**本轮自主细化：**应用公开动作以稳定产品会话身份为目标，返回动作身份、结果类别和必要的已提交版本；查询提供快照、稳定历史游标及可取消订阅。UI 连接带连接代次，丢弃旧代次更新；允许合并流式展示更新，重连以快照纠正，避免要求恢复每一帧通知。协议不暴露 SDK 内部类，也不引入本地 HTTP 服务作为默认依赖。

启动顺序为读取原生控制、取得唯一存储所有权、提供有效同步 bootstrap settings／Models 值，再 open 且保持不调度；随后装载／迁移权威配置、发布运行投影并开放调度。open 自身会调用同步 getter 且可能写入，bootstrap 回调不能访问尚未初始化的 Harness。验收须在 open 阶段实际触发 getter，证明不依赖“open 完才会读取”的假设。应用登记与执行上下文继承分开，内部会话创建不会复制产品可见性或原生草稿。

**仍需验证：**实际 IPC 和原生库集成遵循 T01/T02 的结果。该票的最小提交路径不宣称已经完成跨来源发送意图恢复；T07 承接崩溃窗口的完整投递契约。正常响应时的停止可贯通 SDK，JS 无响应和外部命令的停止保证由 T11 完成。

## Test seam

主入口为应用创建／提交／查询／观察／停止 Interface，使用真实 Pi Durable 1.5.0、已验收持久 Storage 和受控模型／平台 Adapter。断言公开状态、重开后的数据及输入数量，不断言内部转发次数。另以 Android UI 重建与双进程重连验证平台接线。当前项目没有既有生产测试套件；先例是 Module 设计中的高层行为边界及固定 SDK 契约研究。

## Scope and execution boundary

本票交付最小可用纵向会话路径，不包含完整 Console 页面、真实 Provider 配置、附件、Termux 执行或全部自动续跑。本次仅发布设计工单；`ready-for-agent` 不代表已获实现、安装 SDK／APK、启动验证工程或操作设备的授权。
