# Android 本地 Agent 首版 spec

设计基线：2026-11-03；整理完成：2026-11-04。状态：设计与工单已收敛，待后续实施；未运行产品工程或设备验证。

本 spec 依据已确认需求、ADR 0001—0008 与最新交接。Q27—Q35 已全部接受。下文明确区分用户已确认方向、代理为本轮收敛的工程设计、仍须验证的兼容性事实；不再逐字段访谈。

## Problem Statement

用户希望在 Android 手机和平板上直接让个人 Agent 处理真实文件、脚本和日常工作，而不是通过手机遥控 PC。现有终端或桌面后端移植方式往往需要反复开终端、重启服务，界面关闭或系统回收后也难以判断输入是否已发送、文件是否已修改、工作能否继续。

用户需要以会话为中心的简单入口：不用先建项目即可开始，长文本和附件准备不因引擎故障丢失，中断后在条件允许时自动续跑，已完成的副作用不无故重复，主动停止后不复活。省流、系统授权、模型凭据和后台限制必须如实呈现。

当前项目只有需求、设计、研究与已确认的 UI 原型，尚无生产工程、测试套件或 Android 实测结果。因此交付必须先排除运行宿主与受管 Termux 启动的关键可行性风险，再逐步贯通用户行为。

## Solution

交付一个 Android 16 起、ARM64 的个人本地 Agent。正式界面采用 WebView 中的 React，与 Kotlin 原生宿主协作；本应用独立运行进程中的 TypeScript 核心复用固定 Pi Durable / Pi AI 1.5.0。独立官方 Termux 提供完整命令行与兼容工具安装环境，主 Agent 留在本应用。

用户打开会话即可输入、选图或选文件，查看回复、模型、上下文、YOLO 与执行状态；可按需关联项目、查看文件变更或转交请求给明确的其他会话。手机沿用已批准 Console v2，横屏平板提供展开侧栏与右侧辅助区域。首次初始化由应用给出完整操作与可复制命令，随后普通冷启动和恢复由应用管理。

同一应用 Interface 负责创建、提交、查询、订阅、配置与停止；草稿、发送意图、SDK 接纳、运行状态和外部执行证据分别保存和核验。可恢复工作自动继续，未知副作用先核验，不能核验时暂停相关工作并说明原因。

## User Stories

1. 作为手机用户，我希望打开应用就能新建会话，以便不经过项目设置开始工作。
2. 作为用户，我希望未关联项目的会话使用默认工作区，以便无需新建目录。
3. 作为用户，我希望每个会话保留独立历史和状态，以便同时处理不同工作。
4. 作为用户，我希望手工创建和选择项目，以便组织持续工作的位置。
5. 作为用户，我希望共享目录的会话看到同一批文件，以便理解工作区并非隔离沙箱。
6. 作为手机用户，我希望保留独立首页与统一的详细页导航，以便快速找到会话和设置。
7. 作为聊天用户，我希望看到当前模型、上下文占用和 YOLO，以便理解执行配置。
8. 作为聊天用户，我希望从顶栏直接新建会话，以便快速切换工作。
9. 作为聊天用户，我希望通过独立详情按钮打开可滚动配置面板，以便不挤占对话。
10. 作为聊天用户，我希望附件加号打开紧凑菜单，以便选择图片或文件。

22. 作为用户，我希望已开始的工作保持原位置，以便修改项目不会令执行悄悄换目录。

24. 作为用户，我希望首次环境配置有完整命令、复制入口和成功检查，以便不自行拼接启动步骤。

## Implementation Decisions

以下“已确认”来自用户与 ADR；“代理细化”是本轮直接收敛的设计，不声称用户逐项选定实现参数。

### 1. 运行结构与验证门槛

- **已确认：**WebView + Kotlin，TypeScript + React + Vite；构建产物随 APK 分发，不运行 Vite 开发服务器。UI 与本应用运行宿主分进程；TypeScript 负责业务协调，Kotlin 负责 Android 机制与必要紧急控制，SDK 保留执行状态机。
- **已确认：**主 Agent 复用 Pi Durable / Pi AI 1.5.0；完整 Termux 只承接工具执行。一个活动 SDK Session 拥有共享 Storage 写入；这不要求所有会话串行。
- **待验证：**Javet Android Node 是首个候选，需完成模块加载、SQL、网络流、取消、关闭重开、ARM64 与 16 KB 交付验证。验证失败先记录最小反例，比较应用自有 Node 或其他候选；改变既定承诺才复审，不静默降低 target、移主 Agent 到 Termux 或退成有限工具箱。
- **代理细化：**本应用内优先用绑定 Service/Binder 连接原生宿主，WebView 通过受限消息 Interface 访问 Kotlin；仅可信随包页面获得能力，外部导航不继承特权。外部 Termux 传输通过 T03 验证后固定，必须核验调用者、协议版本与会话握手；本机端口存在本身不是就绪证据。

### 2. 数据所有者与动作 Interface

| 事实 | 权威所有者 | 调用者能做什么／观察什么 |
|---|---|---|
| 正式历史、SDK 接纳及执行 | 运行宿主内唯一活动 SDK Session | 创建会话、提交、查询、观察；调用者不直写 SDK 内部表 |
| 产品登记、项目、工作区、新会话默认模型、公开连接定义 | 核心组织的 SDK 自定义 documents／必要 entries | 查询与带期望版本的配置修改；返回冲突或生效版本 |
| 文字／附件草稿、待接纳发送意图及内容持有关系 | Kotlin 原生输入持久化 Module | 按会话读写版本、固定发送内容、核验接纳回执 |
| 停止意图与控制代次 | Kotlin 原生控制记录 | 不依赖 JS 保存停止、查询控制状态、阻止旧代次执行 |
| 凭据密文与保护密钥 | 原生凭据 Module／Android Keystore | 保存、替换、移除秘密；普通查询仅返回配置状态 |
| 外部命令与文件效果 | 工具环境与可核验执行证据 | 启动、观察、取消、核验；无法核验返回不确定 |
| 系统授权、网络与系统启动条件 | Android 平台事实 | 检查、必要系统交互、订阅变化；不以已存布尔值替代事实 |
| 页面投影、流式暂态与缓存 | 可重建视图 | 重新读取权威快照；不作为耐久或接纳证据 |

- **代理细化：**统一的应用 Interface 包括创建／查询会话、保存草稿、发起或查询发送、观察会话、请求停止、查询／修改项目与模型配置、检查环境与明确路由。不逐个镜像 SDK／JNI 方法。
- 每个变更动作携带稳定操作身份、目标身份、期望版本及相关控制代次；返回已完成结果、明确拒绝，或未确认且可按同身份核验。停止、保存、SDK 接纳、工具接纳与外部完成是不同确认。
- 观察从完整快照开始，带宿主实例与单调视图版本，之后提供可合并的更新。重连先读快照；过期实例消息丢弃，缺口重新取快照；不承诺恢复每个 token／watch 通知。运行断连不是会话失败或完成。
- 大内容／大输出分块读取或经受控引用传递，带完整性与截断标记，不挤入单条 IPC；引用访问仍检查归属及存活关系。具体上限以验证结果设置，越限必须显式失败或提供已说明的缩减方式。

### 3. 存储、启动与记录语义

- **已确认：**SDK 主存储目标 SQLite；产品会话显式登记并一一对应 SDK conversation；内部 task-owned conversation 不自动进入产品列表。标题、项目名称和普通设置提供当前值，不新增完整编辑审计。
- **代理细化：**产品登记与初始模型在 SDK 会话创建的提交中写入，创建动作保存稳定查找身份；首次提交另走接纳事务。应用 document 明确 scope、版本、fork 与保留规则；产品登记、草稿与发送意图不因内部 fork 自动复制，子会话执行位置显式继承。
- 普通配置用可重建同步投影满足 SDK Models/settings 的同步读取契约。启动顺序固定为：读取原生控制、取得唯一写入所有权、提供有效同步 bootstrap 值、open 且不调度、装载／迁移权威配置与模型定义、发布投影，最后开放调度。open 自身会读同步 settings 且可能写入；bootstrap 回调不得依赖尚未初始化的 Harness。submit、wait、onWake 等同样经过就绪闸门。
- **代理细化：**原生输入／控制记录使用独立原生 SQLite，由统一 Kotlin Module 在短事务中协调跨进程读改写；不写 SDK 库，不使用 SharedPreferences 充当跨进程权威。驱动、事务与耐久配置须验证，不宣称跨库事务。
- 应用私有工作数据放在首次解锁后可用的 CE 域；从首个可写版本就应用备份排除。各存储提交成功才返回相应保存确认，UI 渲染或入队不算耐久。

### 4. 草稿、附件与可靠发送

- **已确认：**原生独立保存每会话文字／附件草稿及待接纳发送意图；恢复不自动发送草稿。附件保留来源与必要物料化内容，不承诺完整原件备份。
- **代理细化：**草稿携带递增 revision，写入与清空按期望 revision 条件执行；初始自动保存采用 250 ms 防抖、最长 1 s 合并等待，切会话和显式发送请求 flush。只有成功确认的 revision 标为已保存；突然终止前未确认的编辑不承诺零丢失。这些数字是可测量调整的初始工程值。
- 编辑时在本地逐步准备文本／图片输入，发送前固定成功采用的内容版本与摘要。原件变化不改写旧输入，来源失效、转换未完成、格式不支持或预算超限分别显示。未发送准备不调用云端模型。
- Pi AI 的通用消息采用 text／inline image；应用的 URI 或 blob 引用不直接冒充模型已读取的内容。图片在 SDK Interface 满足其内联内容契约；文件可以提供明确范围的文本／图片表示或清楚标示仅有来源引用。输入预算与原件大小分开。
- 同一次发送保存目标、request identity、内容摘要／版本、排队意图、位置预期与控制代次。原生保存后才尝试 SDK 接纳；准备未完成只能显示待准备，不能显示已接纳。
- 核心在同一个 SDK commit 中先调用受支持的 submit 接纳入口，并在正确的事务顺序中核验／记录应用接纳映射和绑定。SDK requestId 去重不比较同类型内容，因此应用必须先按稳定意图检查目标与内容一致；不一致拒绝，不能静默返回旧 submission。
- 原生回执与 SDK 提交是两个来源。崩溃后先查询接纳映射，再重投同一身份；确认丢失不创建新发送。用户主动再发相同正文使用新身份。接纳后仅清理对应旧 revision，后续草稿保留。
- 接纳、排队／放入 transcript、模型实际采用与完成分别观察；一个发送不是一个 run，也不是一个 generation。内部自动后继工作由 SDK 处理，宿主不另造输入调度器。

### 5. 工作位置、执行证据与并发

- **已确认：**工作区有稳定记录，身份、位置与访问能力分离；SDK 接纳时固定位置。在尚未结算输入、相关后台任务／后代、待确认发送或未决外部效果仍使用该位置时，拒绝修改相关会话及共享项目／工作区关联；不静默排队配置修改。
- **代理细化：**核心持有应用绑定身份与版本，涵盖多个 SDK generation 和自动后继工作；不把 generation taskId 或 idle 当绑定生命期。释放须证明相关使用已结算；无法核验时保留占用，不能仅因超时或进程死亡释放。
- 所有主动接纳路径包括 UI、Agent 与扩展路由都经过同一检查。恢复与子会话继续使用原绑定，同时重新核验当前授权与真实位置；位置冻结不冻结文件内容、目录移动或外部应用活动。
- 工具环境统一承接 SDK 文件与 shell，报告就绪、接纳、运行、完成、取消确认、失败和不确定。每次受管执行有稳定 execution identity、参数摘要、绑定版本、控制代次和可核验证据；SDK 存储提交收据不当作外部效果收据。
- Termux 侧保留受管命令身份、退出／输出与所能确认的进程关系。断线先关联已存在执行并核验，不默认重复 launch；取消只作用于受管执行及可证明归属的后代，不杀无关 Termux 工作。任意命令没有天然 exactly-once 保证。
- 实际目录的潜在写入由核心保守串行。先由工具环境解析规范位置／别名／覆盖范围，再取得执行占用；未知命令按可能写入处理，不能确定写入范围时采用该执行环境的保守互斥。聊天和已界定的纯读取不因此全部阻塞。
- 环境级未知范围占用与该环境全部局部写占用双向冲突；目录包含关系也属于冲突。原生与 Termux 入口若指向同一原文件，使用同一资源协调身份；无法排除跨入口别名冲突时退到覆盖所有相关可写入口的共同串行域，不能按 Adapter 名称分锁绕开。
- 首版至少贯通一条真实授权原文件路径：文件读取、shell 修改、文件复查面对同一对象。SAF URI 不伪装 POSIX 路径；需要中转时明确副本身份、回写、冲突检查和失败语义。不能实现某访问方式时报告能力限制。

### 6. 停止优先与自动续跑

- **已确认：**进程恢复不等于重发最后一条消息；可恢复中断在条件满足且系统允许运行时自动继续。主动停止后不自动复活；系统 force-stop 等用户重开。
- **代理细化：**原生先耐久保存停止 fence／控制代次，再要求核心通过 SDK 支持的中断入口协调，并独立请求工具环境取消。JS 无响应时原生仍可封锁新 dispatch、终止本应用运行宿主并控制受管外部执行。停止记录保存失败要显示，不能谎称停止已耐久。
- 所有模型发起／投递、工具 dispatch、SDK wake、重试和重连恢复都检查停止代次。停止前的未接纳意图不自动重投；迟到结果可记录为证据，但不能触发旧工作继续。仅用户明确新发送建立新一代；旧未决外部效果仍须核验与占用协调。
- 同会话的新意图可以先原生保存，但须等待旧停止针对 SDK 的 abort 已提交并核验完成范围后才能接纳。SDK 会话级 abort 不认识应用控制代次，不能让迟到旧 abort 误撤回新输入；这是一道接纳屏障，不是新建 SDK 调度器。
- 外部仍可能运行时显示“已请求停止，外部结果未确认”，直到证据充分；杀掉 JS 不等于外部取消成功。未知副作用暂停相关路径，已确认完成的效果按证据继续，不从头重做。
- 正常 close、crash、网络错误、系统回收、首次解锁、再次锁屏、用户停止与 Android force-stop 分别处理。UI 关闭不主动停止 Agent；系统限制允许时运行可见的前台工作与完成通知，类型与合法启动路径必须通过 T12 证明，不宣称永久保活。
- 重试沿 SDK attempt／restart 预算，宿主补充可见等待与平台门控，不叠加乘法重试。初始恢复探测按 1／2／4／8／16 秒、最多 5 次后显示需要处理；尊重 Retry-After 和更严格 SDK 限制。同一工作预算持久化，宿主重开不重置。重新获得条件可触发核验，不构成无限重发模型请求；不承诺零重复计费。

### 7. 省流与系统条件

- **已确认：**YOLO 不增加逐操作审批；系统授权、环境就绪、省流、停止、工作区排队与未知效果核验仍有效，各有原因状态。
- **代理细化：**省流以 Android 网络事实识别受限／计费网络；受控工具声明模型通信、已证明纯本地、非模型联网或行为未知。只凭程序路径或是否随包安装不能证明任意参数／脚本／子进程纯本地。
- 策略落在最终实际执行 Interface，含 SDK safe replay 路径。网络变为受限时，受管非模型联网尝试停止并核验效果，不能安全暂停的命令不假装已暂停；未知结果按执行核验规则处理。
- 临时放行限定明确操作和网络条件，界面显示范围；不用通用审批队列实现。模型通信和已界定纯本地操作可继续。跨 UID 本机桥传输与业务互联网访问分开，不承诺任意代码的系统级硬断网或切换瞬间零流量。

### 8. 模型连接与秘密

- **已确认：**应用共享 Provider 配置和凭据，每会话独立模型选择；新会话显式初始化创建时默认值。复用 Pi AI 模型目录、协议、流式与鉴权，不建立另一套 Provider 框架。
- 切模型在后续 prepare 生效；普通 retry 可能重读新选择，在途请求不强制重发。正常 close 的原请求恢复、deferred handle 与已 select 的 compaction 保留 SDK 各自规则；crash interrupted 的重试不混同正常 close。
- **已确认：**改变目的地或不兼容协议使用新连接身份；保留仍被引用的旧定义，新连接不自动继承旧 Key、不自动迁移既有会话。校验覆盖鉴权可覆盖的最终端点，不只比 UI URL。
- **代理细化：**凭据轮转只作用于后续鉴权解析，不声称撤回已发请求。同连接普通请求可用当前凭据；持久 deferred handle 遇到无法证明兼容的账户／凭据变化时阻止盲目换账号恢复，清楚报告不可恢复或需重新发起，不尝试猜测账号相同。
- Keystore 保存保护密钥，密文在私有 CE；首次解锁后不额外要求每次认证或当前持续解锁。暂不可用、密钥丢失／永久失效、损坏与版本不兼容分别呈现，不能退为明文或删除历史草稿。
- 原始 Key 仅经专用配置动作进入凭据 Module，并在 Pi AI 请求时鉴权 Seam 使用。普通查询、状态广播、SDK 可持久化请求选项、错误与日志不含原始 Key／认证 headers。用合成秘密验证全链，不能靠类型声明或错误截断当作脱敏。

### 9. 扩展与跨会话路由

- **已确认：**一份薄应用描述关联可选 React UI 与 Agent 入口，各宿主只加载各自代码；Agent 贡献交 SDK registry。内置能力使用同一接入机制，UI-only 不需要空后台扩展。
- **代理细化：**描述固定稳定应用身份、可选两侧构建入口及对应 SDK 身份；装配时报意外重复。SDK 允许的有意工具／section 覆盖沿原规则，重复 task 名按 SDK 报错，不另造通用插件调度器。
- UI 能提供真实自定义展示和交互，通过应用 Interface 查询／订阅和动作；UI 卸载清理其订阅与界面资源，不停止 Agent。持久化、停止、平台检查和执行门控留在固定核心。
- 路由以明确目标会话和稳定路由操作身份查询／创建／转交。转交调用统一可靠接纳 Interface，不直接调用 SDK 绕过位置和停止检查；源会话显示目标及接纳结果，目标不自动获得其他会话全部上下文。明确转交失败不自动换目标或创建多个会话。

### 10. 保留、迁移与界面真实状态

- 正式历史和仍被引用的输入内容不按时间过期。应用可回收可重建缓存及证明无引用的材料；未确认提交、停止记录、旧连接、绑定或未知效果相关内容不得提前回收。
- **代理细化：**SDK、原生输入和工具环境分别扫描引用，以保守保护集合产生清理候选；原生内容持有 Module 负责新增引用的持有登记与候选隔离。发布新引用前先取得耐久持有，跨来源交接完成前旧所有者不释放唯一持有。删除前以内容版本条件隔离候选并重新核验引用；隔离期间新增持有必须取消清理或拒绝后重试，不能只靠一次扫描删除。任一来源不可读、迁移中或核验未完即延期清理，不假定跨库原子引用计数。磁盘满停止受影响的新写入并报告失败，不删正式历史换取成功。
- 迁移采用带版本和成功标记的受控流程；失败保留原数据并关闭恢复入口，支持安全查询时才开放只读视图。不用空库替换损坏或不兼容数据；升级与卸载重装分开说明。
- 私有会话、执行、草稿、输入、控制与凭据排除系统云备份、D2D 和适用新增迁移通道；从首版布局配置并设备验证，不能只用 allowBackup=false 声称完成。此策略不控制 Termux 或用户原件，也不承诺所有厂商工具不可提取。
- 首版不交付单会话历史物理删除，不用隐藏、退休 document 或清空模型上下文冒充。原文件操作继续按授权能力执行，不与删除产品记录联动。
- UI 使用真实的保存／接纳／执行／恢复状态；上下文或文件变更数据不可得时标明未知，不能填原型示例。语音占位、原型控制条与模拟权限开关不进入正式功能。
- 受管文件操作提供关联会话／执行身份、位置及原件／副本标记的变更事实；取得前后内容时提供有界文本 diff。未知 shell 修改范围或缺少前值明确降级，不承诺完整文件系统审计。详情面板支持当前会话内搜索、定位与前后会话切换，不扩展为全局搜索。

## Testing Decisions

- **主要 Seam：**调用者与测试使用同一应用 Interface，围绕创建、保存、提交、观察、配置和停止断言外部行为。采用真实 Pi Durable 1.5.0、持久存储及受控模型／平台／执行 Adapter；测试持久重开结果、可见状态和实际效果，不断言私有状态机、转发层调用次数或内部表布局。
- **现有先例：**本仓库没有生产测试或已存在的实现 Seam。可复用的是 Module 设计的行为测试方向、研究整理的 SDK conformance 场景、1.3.0 原验收清单与 1.5.0 增量差异。它们是待实现测试依据，不能写成已通过测试。
- **必要附加契约：**SQLite 必测 STRICT、JSON、runCounted、原子 batch、事务隔离、flush／耐久收据、重开和迁移；MemoryStorage 不证明耐久。ExecutionEnv 必测同一文件命名空间、取消和未知效果；模型传输必测 UTF-8 流、取消、deferred 与凭据不落盘。
- **Android 边界：**双进程、JS 无响应、跨 UID、正常冷启动、外部进程死亡、重启首次解锁、再次锁屏、授权撤销、force-stop、通知／前台运行与备份排除须在设备验证；纯逻辑测试不替代它们。
- **故障注入：**在草稿提交前后、意图提交前后、SDK 接纳前后、回执前后、附件准备中、目录绑定竞争、命令启动／副作用／退出／SDK 记录之间逐点中断。使用可计数、可验证的测试文件效果证明没有盲目重放；无法验证的命令必须停为不确定。
- **竞态：**覆盖同身份异内容、旧保存／旧 ACK 迟到、两个 UI 连接、宿主抢占写入者、并发路由与停止、目录别名／包含关系、stop 与 wake／retry／网络切换的所有关键交错。新发送不解除旧未知副作用的占用。
- **机密与恢复：**使用合成 Key 检查 SDK 检查点、generation／compaction、错误、日志、消息广播与支持的备份路径；密钥失效不删除业务数据，凭据变更不将旧请求送新目的地。
- **UI：**按已批准原型验证手机和横屏平板的导航、紧凑附件菜单、详情面板、提问浮条、状态及文件变更区；每个行为票提供最小可用 UI，不把所有接线推到最后一张界面票。
- **完成证据：**每张票记录固定依赖版本、设备／模拟器范围、执行步骤、预期／实际、故障点和未通过限制。T01—T03 的失败阻断依赖票，不以“能加载 hello world”或一次 warm start 当可行性通过。
- **首条验收：**小米 15 与 Galaxy S23（用户报告 Android 16，执行前核验）分别创建无项目会话、处理真实授权文件，注入断网／进程退出后自动继续，核对已完成效果未重复、未知效果未盲重放、主动停止不复活、初始化后普通启动不依赖手工开终端。平板布局与功能保留；计划平板型号／系统确认后补真实设备记录，不冒称已通过。

## Out of Scope

- 产品级独立任务中心、PiP／系统悬浮助手、默认自动分流、Cron、宠物、独立多 Agent 管理与专门子代理编排。
- 完整桌面 HTTP 后端移植、外部 Termux 承载主 Agent、应用占用 com.termux 身份或自有 Termux 包仓库。
- Google Play 上架、商业账号、Android 16 以下和 32 位 APK 适配；开发模拟器不扩大产品支持承诺。
- 订阅 OAuth、逐操作审批队列、逐文件上传审批、通用防泄漏系统、任意代码的系统级网络沙箱。
- 动态手机安装 JS 插件、插件市场、核心热更新、所有桌面 Pi 扩展直接兼容、具体 timeline 插件的移植。
- 分享菜单导入、独立产物预览与导出、完整 IDE／文件树／终端界面、独立网页搜索、长期记忆、ADB／无障碍手机控制、桌面协同与 IM 桥。
- 单会话历史物理删除、云同步、自动换机恢复、完整原件归档、无限日志／容量、强行停止后自行绕过限制、永久保活和模型零重复计费承诺。
- 本次仅完成设计、仓库和 issue 发布；生产实现、验证工程、安装 SDK／APK／运行时、运行上游二进制和修改设备留待后续明确指令。
